# Stage 10 · 截图解析（decode）

> 只回答一个问题：**这张图里有什么结构、什么取值，它们分别映射到哪个 lobe-ui 组件和哪个 token。**
> 只在 screenshot-restore 场景运行。产出两张表，30 和 50 照着表执行，不再回头凭感觉看图。

还原失败通常有两种：一是逐像素抄 hex 和 px，绕过了设计系统；二是凭印象「差不多」，丢掉了图里真正的层级。本 stage 把图拆成可执行的清单，避免这两种失败。

## 聚焦

- 区域清单：从上到下、从左到右，每块区域承担什么（导航 / 主任务 / 辅助 / 状态）
- 每块区域里的信息单元，以及它们的语义（状态、分类、动作、容器还是导航）
- 取值采样：主要颜色、字号档位、间距档位、圆角、阴影、边框
- 取值 → token 映射；映射不上的写成 D-11 缺口
- 截图**看不到**的东西：交互态、空 / 加载 / 错误、窄屏（列给 70）

## 不负责

- 选具体组件、写导入 → 30（本 stage 只写「语义 + 候选组件」）
- 判断截图好不好看、要不要改 → 不改。还原就是还原；有明显问题记一行建议给 80
- 业务分析 → 00 已用 `reverse` 模式做过
- 写代码。

## 输入

- 截图 / 设计稿（必需）；00 的 `reverse` brief
- 有多张图时：明 / 暗、桌面 / 移动各算一张

## 只加载

- [design.md](../references/design.md)：D-02 视觉角色 → token · D-04 几何与排版取值 · D-05 预设色阶 · D-11 合法失败格式
- 不加载 components.md：组件选型是 30 的事，这里只写候选。

## 步骤

1. 按 00 brief 的「第一视线落点」确认主区，再从主区向外列区域。
2. 每个区域列信息单元，标语义；同一外观、不同语义的单元分开列。
3. 采样取值。颜色按「角色」归类（主文本 / 次文本 / 边框 / 表面 / 强调 / 状态），不按出现次数归类。
4. 每个取值找 token：`colorText` / `colorTextSecondary` / `colorBorderSecondary` / `colorFillTertiary` / `borderRadiusLG` / 间距档位 4/8/12/16/24…。差 1–2px 或色值接近时，**用 token，不用截图的原值**。
5. 映射不上的写 D-11 缺口；不要悄悄写 hex。
6. 列出截图没有覆盖的状态和视口。

## 输出（30 / 50 / 70 直接消费）

```
[10 · decode] 完成
区域清单：
| # | 区域 | 职责 | 信息单元（语义） | 候选组件 |
| R1 | 顶栏 | 导航 | 标题(文本) · 返回(动作) · 环境(分类) | PageHeader / Tag |
取值映射：
| 采样 | 角色 | token | 偏差 |
| #8c8c8c 13px | 次文本 | colorTextSecondary · fontSizeSM | 一致 |
| 18px 间距 | 区块间距 | 16 或 24 | 取 16（密度高） |
缺口（D-11）：<无 / 列表>
截图未覆盖 → 70：hover · 空态 · 加载 · 错误 · 390px 窄屏 · 暗色
建议（不执行）→ 80：<截图本身的问题，例如对比度不足>
```

## 检查清单

1. 每个区域都标了职责，且主区和 brief 的第一视线一致。
2. 外观相同、语义不同的单元分开列（例如「运行中」状态 vs「生产」分类）。
3. 取值映射表里没有「原值直用」，只有 token 或缺口。
4. 列出了截图未覆盖的状态和视口。
