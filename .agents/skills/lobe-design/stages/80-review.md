# Stage 80 · 上线前审查（review）

> 只回答一个问题：**这一版能不能放行；如果不能，最该先改的两三件事是什么、回到哪个 stage。**
> 生成和评估隔离：本 stage **只记录、不修**。修复由回流目标 stage 完成。

## 三种模式

| 模式 | 用于 | 做什么 |
| --- | --- | --- |
| `audit` | pre-launch 场景；「能不能上线」 | 脚本全量扫描 + 五项技术体检 + 六维评分 + 阻断项 |
| `critique` | launch-visual 场景 | 在 audit 之外，看截图做设计评审（一秒印象、眯眼、遮 Logo、对齐线、留白、字阶、配色比例） |
| `compare` | screenshot-restore 场景 | 对照 10 的区域清单和取值映射表，逐项检查是否还原 |

其他场景（打磨、后台新建、系统统一）默认用 `audit`。

## 聚焦

- 自动化证据：`lint-lobe.mjs` + `check-detail.mjs` 的结果
- 五项技术体检（吸收 Impeccable audit）：可访问性 / 性能 / 主题（明暗）/ 响应式 / 实现完整性（有没有占位、TODO、假数据），每项 0–4 分
- 六维评分与阻断项：按 [evaluator.md](../references/evaluator.md)
- 原型的「常见错法」逐条对照（admin-archetypes P-xx）
- 把每个问题归因到规则 id 和 stage，作为回流目标

## 不负责

- 不在审查过程中顺手改代码。
- `lint` / `type-check` / 单测 / 构建通过只是前置条件，一行带过即可，不作为评分项。

## 输入

- 00 brief（主任务、关键决定 → 「主任务不明」「主路径断裂」两条阻断项）（**必需**）
- 前面各 stage 的交接（改动、遗留、缺口）
- 真实渲染的界面（截图、明暗各一张），拿不到就如实写「证据缺失」

## 只加载

- [evaluator.md](../references/evaluator.md)：全文
- [admin-archetypes.md](../references/admin-archetypes.md)：只读 brief 标注的 P-xx 的「常见错法」
- 需要归因时，按规则 id 查对应 reference 的那一条（本 stage 允许引用任何规则 id，但只读被命中的那一条）

## 步骤

1. 跑脚本：`node scripts/lint-lobe.mjs <路径>`、`node scripts/check-detail.mjs <路径>`。
2. 汇总前面各 stage 的「遗留」，确认是否已被对应 stage 处理。
3. 五项技术体检各打 0–4 分；六维评分时先写证据和扣分原因，再聚合分数。
4. 查阻断项。命中任意一条 → 不放行。
5. 按回流表归因，最多列 3 条，按影响排序。归因时优先用**模型的语言**（M-03 第几条 / M-02 哪条原理），比「感觉不对」可执行。
6. 有回流时：回到目标 stage 修复，然后**最多再确认一轮**（有界验证，不做开放式循环）。

## 检查清单

1. 两个脚本都跑过，并贴出 RESULT 行；没跑成要写明原因。
2. 五项技术体检和六维评分都先写证据、再给分数。
3. 阻断项逐条对照过 brief 的主任务和关键决定。
4. 每个问题都归因到规则 id 和回流 stage，最多 3 条。
5. 审查过程中没有改代码。
6. 文案（只核对，不重写；细则在 75-copy）：profile 已选且全页一致 · 人称一致 · 术语唯一 · 中西文留白与全角标点 · 确认 / 错误文案按 profile 写清后果和出路 · 没有补造的数字或承诺。任一不满足 → 回流 75。
7. 截图证据：明暗各一张（critique / compare 模式还要有 390px 视口）；拿不到就标为「证据缺失」，不要写成「应该正常」。

## 回流表

| 问题属于 | 回到 |
| --- | --- |
| brief 错了（主任务、关键决定、优先级） | 00 |
| 截图映射遗漏或错误 | 10 |
| 方向是品类默认、记不住 | 20 |
| 导入入口、骨架、组件语义、生态包、手写了组件已有的东西 | 30 |
| 层级、主路径、该有哪些文案、冗余 | 40 |
| 取值、间距、字阶、密度、明暗、动效、AI 味 | 50 |
| 跨页面不一致 | 60 |
| 状态、边界、反馈、空 / 错 / 确认文案缺要素、a11y、响应式 | 70 |
| 措辞、语气、人称、术语、中文排版、profile 选错 | 75 |

## 停止规则

- 达到阈值且没有阻断项 → 通过
- 回流修复后确认一轮仍未通过 → 停下，报告卡在哪里，不再开新一轮
- 修订后分数下降 → 退回之前更好的版本
