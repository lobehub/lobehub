# Stage 40 · 信息架构、交互与文案（flow）

> 只回答一个问题：**用户能不能看懂这一页、按 brief 的优先级找到信息、走完主路径。**
> 文案的**决定**（有哪些标题、说明、按钮、确认框，按钮用哪个动词）放在本 stage：它们依附于某个决定或动作。**措辞与排版**（语气、人称、术语、中文排版、按产品类型的写法）交给 75-copy，它在宏观 pipeline 里固定跑，不会没人负责。

## 聚焦

- 页面顺序是否服务 brief 的「关键决定」；信息层级、分组、主次
- 主链路与分支链路；选中、详情、反馈是否互相响应
- 简化（吸收 Impeccable `distill`）：可以删掉的字段、步骤、按钮、确认框
- 澄清（吸收 Impeccable `clarify`）：标题、说明、动作文案是否用产品自己的语言
- 危险操作的确认强度与结果反馈（按 brief 的可撤回性和波及面定）

## 不负责

- 组件选型、导入、骨架外壳 → 30（结构让主路径走不通时，记 `遗留 → 30`）
- 间距、颜色、字号、圆角、动效、AI 味 → 50
- 空 / 加载 / 错误 / 禁用 / 极端输入 / 键盘 / 窄屏的**逐项加固** → 70（本 stage 只在 L5 里**列出**需要哪些状态）
- 措辞、语气、人称、中文排版、按产品类型改写 → 75
- 打分 → 80

## 输入

- 00 brief：主任务、关键决定、决定所需信息、危险操作、来路去路（**必需**）
- 原型对应的「第一屏优先级」和「常见错法」（admin-archetypes P-xx）
- 已有代码或截图（打磨模式）

## 用模型定位「哪里卡住」

### M-01 的后两个钻（Develop / Deliver）

- **Develop**：对 00 给的解法候选，产出 L2 区域方案。**要给出 2 个互斥候选**，不要一上来就写一个。
- **Deliver**：产出 L5 状态清单和 L6 验收标准。这一步不能跳——模型倾向于先做成功态，因为它最像一张完整的截图。

### M-06 福格行为模型（B = M · A · P）

**一个动作用户没做，只可能是三者之一缺失。** 不要笼统地说「CTA 不显眼」，先判断缺哪个：

| 缺什么 | 症状 | 怎么补 |
| --- | --- | --- |
| 动机 M | 按钮在，但用户不觉得自己该点 | 把动作挪到 brief 的关键决定旁边 |
| 能力 A | 想点但成本高（要填 8 个字段、要跳两页） | 减字段、给默认值、分步（W-07） |
| 提示 P | 用户根本没看到入口 | 提权重、上移到第一屏、用 primary |

判断错会白费功夫：**缺 A 时把按钮调大是无效的**，该做的是减少输入。

### M-08 认知负荷（Hick / Miller）

- 并列选项 > 7 个 → 先分组或收进 `Select`；主 CTA 唯一（W-01）。
- 一屏区块数 > 7 → 先分层（折叠、渐进披露、默认收起），不要靠缩字号硬塞。

## 两种模式

- **规划模式**（operate-build 场景，在 30 之前跑）：只产出 L1–L6，不写代码。
- **打磨模式**（product-polish 等场景）：对照下方清单调整顺序、删冗余、改文案。

### 规划：L1–L6

```
L1 定位与意图   一句话定义 · 非目标 · 行为边界（直接引用 brief，不重写）
L2 信息架构     区域 · 区域顺序（= brief 的决定所需信息）· 内容增长规则（多到 1000 条怎么办）
L3 核心链路     对象状态清单 · 主链路 · 分支链路 · 每一步的入口和出口
L4 组件功能     每个区域的功能清单（不写组件名，组件名是 30 的事）
L5 状态清单     需要哪些状态：空 / 加载 / 失败 / 无权限 / 部分失败（只列，70 负责做）
L6 验收标准     Given / When / Then；完成的定义
```

最容易被跳过的是 L5 和 L6：模型倾向于先做成功态，因为它最像一张完整的截图。

## 检查清单（启发式，借鉴 Impeccable critique 的「先看路径再看像素」）

1. 第一屏回答 brief 的关键决定；和决定无关的字段已降级到详情、抽屉或折叠区。
2. 页面里只有一个主动作，且它对应 brief 的主任务（W-01）。
3. 主路径没有死胡同：每一步都有出口；选中态、详情区、反馈状态同步。
4. 危险操作的确认强度和可撤回性、波及面相匹配；确认按钮是动词 + 对象（W-01）。
5. 简化（W-07）：每个字段、按钮、步骤都说得出它服务哪个决定；说不出的删掉或降级。
6. 标题和说明用产品自己的语言，是陈述句，不是营销腔（W-02）。
7. 专名、状态词、口径在全页和侧栏入口一致（W-03）。
8. L5 状态清单已列出，并交给 70。
9. **M-06**：主路径上每个关键动作都判断过缺的是 M、A 还是 P，并据此给出改法。
10. **M-08**：并列选项 > 7 时已分组或收进选择器；一屏区块数 > 7 时已分层。

## 症状 → 规则

| 症状 | 规则 |
| --- | --- |
| 字段平铺、指标等权，看不出先看什么 | brief「决定所需信息」+ P-xx 第一屏优先级 |
| 一屏多个 primary，主动作不明 | W-01 |
| 按钮写「确定」「提交」「OK」 | W-01 |
| 说明是营销腔或在复述标题 | W-02 |
| 同一对象在侧栏和页面里叫法不同 | W-03 |
| 步骤多、确认框多、选项多 | W-07 |
