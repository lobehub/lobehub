> 只在 75-copy 选中 `admin` 时加载。通用规则（T-01..T-09）照常适用。高密度后台是 Tech-Doc-Style「克制、准确、可扫读」最直接的落点。

## T-30 语气、人称与密度

- 人称：**无主语**为默认（`已提交审批`，不是 `您已成功提交审批`）。对外部客户可见的通知、邮件模板可用「您」，在 product.md 写明。
- 语气：中性、客观、不带情绪；不用感叹号、不用表情。
- 密度：高。列名、筛选项、按钮用 2–6 个字的名词或动宾短语；说明放进 tooltip（`TitleWithTips`，见 W-02）。

## T-31 术语与状态

- 动作成对、全站统一：启用 / 停用、上线 / 下线、通过 / 驳回、提交 / 撤回、冻结 / 解冻。不混用「开启 / 禁用」。
- 状态词是名词或「已 / 待 / 中」结构：`待审核`、`审核中`、`已驳回`。状态枚举与筛选项、统计数字同名（W-03）。
- 业务对象名来自业务方术语表；数据库字段名不上界面（`user_status` → 「账号状态」）。

## T-32 空态、错误与确认

| 场景 | 推荐 | 避免 |
| --- | --- | --- |
| 筛选无结果 | `没有符合条件的工单` + 「清除筛选」 | `暂无数据` |
| 批量结果 | `已驳回 8 条，2 条失败（状态已变更）` + 「查看失败项」 | `批量操作完成` |
| 无权限 | `无权限查看风控记录。需要「风控审核员」角色` | `403 Forbidden` |
| 并发冲突 | `该工单已被「李四」处理，刷新后查看最新状态` | `操作失败` |
| 不可撤销确认 | 标题 `删除 3 个商户？` · 内容 `删除后商户数据和历史订单将一并清除，无法恢复` · 按钮「删除 3 个商户」 | `是否确认删除？` |

- 审计相关：写清操作人、对象、时间（`王五 于 2026-10-16 14:02 停用了该账号`）。
- 驳回 / 拒绝必须带原因字段，界面提示「请填写驳回原因」而不是「原因不能为空」。

## T-33 列名、筛选与 tooltip

- 列名用名词，不加「的」、不加单位以外的括号：`创建时间`、`金额（元）`。
- 时间窗、口径写在指标旁（W-03），tooltip 只写定义：`GMV：已支付订单金额，含退款前`。
