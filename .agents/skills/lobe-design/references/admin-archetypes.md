后台页面大多落在下面几种原型里。先在阶段 00 判断这页属于哪一种（可以是两种的组合，例如「详情 + 审计日志」），再按原型决定：用户要做什么决定、第一屏放什么、必须有哪些状态、最常见的错法。

本文只写「什么场景用什么模式 / 组件」和注意事项，不写组件内部实现。组件细节见 [components.md](components.md)，状态与反馈的通用规则见 [craft.md](craft.md)。仓库里有 `ux` skill 时，状态分支、确认 → 进行中 → 结果、草稿保护的行为规则以它为准，本文只说每种原型里哪些特别要紧。

## P-01 总览看板

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 整体是否健康；哪里变坏了；先点进哪里 |
| 第一屏优先级 | 1. 需要处理的异常（突增、超阈值、失败）2. 少数几个能驱动动作的核心指标 + 对比基准（环比 / 阈值）3. 趋势 4. Top 分布 / 排行入口 |
| 组件 / 模式 | 指标用 `StatCard` / `MetricStrip`（等权一组用一条，不拆成一排卡）；趋势用图表卡；分布用 `BarList`；异常列表用小尺寸表 |
| 必须有的状态 | 每块卡片独立加载、独立失败；数据更新时间和刷新；对比口径不可算时说明原因而不是显示 0 |
| 下钻 | 每个代表「一批记录」的数字、条、行都能点进同口径、同时间范围的列表或详情 |
| 常见错法 | 指标等权平铺、没有基准的裸数字；只能看不能点；终身累计数字放在随时间范围变化的看板上；装饰性图表；一个慢查询拖住整页 |

## P-02 列表 / 搜索 / 筛选

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 找到某一个对象；或圈出一批对象去处理 |
| 第一屏优先级 | 搜索（能按 ID / 名称 / 邮箱精确定位）→ 常用筛选 → 表格；批量操作在选中后出现 |
| 列优先级 | 身份列（名称 + 头像 / 图标 + ID）在最左；其次是做决定要看的状态和关键数值；时间靠右；低频字段收进详情，不要为了「信息全」把所有字段铺成列 |
| 组件 / 模式 | 表格 + 工具栏；行操作是图标按钮（不是文字链接）；常用视图用页签或预设筛选（「待处理」「失败」「我负责的」）；筛选、排序、分页进 URL |
| 必须有的状态 | 首次空、筛选落空、加载中、失败是四个不同画面；计数和批量范围覆盖全集，不只是当前页 |
| 批量操作 | 选中后显示「已选 N 项」和可用动作；全量操作写出影响条数；结果写「成功 N・失败 M」 |
| 常见错法 | 只能翻页找人；筛选不进 URL，链接贴出去丢了条件；行点击和行内按钮冲突；一页 50 行远超一屏；失败显示成「暂无数据」 |

## P-03 详情 / 对象页

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 这一个对象现在什么状态、为什么、要不要对它做什么 |
| 第一屏优先级 | 页头：身份（名称、ID 可复制）+ 当前状态 + 主动作；下面是关键属性摘要；再往下是关联对象和历史 |
| 组件 / 模式 | 页头放身份与动作，状态用状态标签；分区用标题 + 卡片，不卡片套卡片；关联对象用小表并能跳过去；历史 / 审计日志用时间线或表 |
| 生命周期 | 写出对象所在的生命周期阶段；只显示当前状态下可用的动作，不可用的说明原因 |
| 必须有的状态 | 对象不存在 / 无权限 / 加载失败分开；写操作后原地刷新该对象，不整页闪 |
| 常见错法 | 详情页是把列表行的字段竖着排；状态藏在第三屏；危险操作和普通操作同色同位；看不到「谁在什么时候改过它」；不挂在所属列表下（面包屑断） |

## P-04 新建 / 编辑表单

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 填哪些值、填对没有、提交后会发生什么 |
| 布局 | 按业务含义分节（基本信息 / 规则 / 权限 / 高级）；必填项在前，高级项折叠；短表单用弹窗或抽屉，长表单用整页；需要预览时两栏（字段左、预览右） |
| 组件 / 模式 | 受控表单从 `@lobehub/ui/form` 进；字段级校验放在字段上，不用顶部错误横幅；提交按钮写动词（「创建角色」而不是「确定」） |
| 必须有的状态 | 提交中禁止重复提交；失败保留已填内容；长表单或整页编辑有离开提醒 / 草稿；编辑并发时提示版本冲突 |
| 常见错法 | 字段按数据库顺序排；一次性校验全部再弹一个错误；关掉弹窗就丢了输入；创建成功后不知道去了哪 |

## P-05 配置 / 设置

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 改不改某个会影响线上行为的值；改完是否生效 |
| 布局 | 按影响范围分组；每项写清楚影响什么、当前值、默认值；高风险项单独一区 |
| 组件 / 模式 | 短设置表单（标签在左或上）；开关只用于立即生效的二值项，需要保存的用表单 + 保存按钮；有版本 / 发布概念的配置显示当前发布版本、草稿和回滚入口 |
| 必须有的状态 | 未保存修改可见；保存中 / 已保存 / 保存失败；生效延迟（缓存、发布流程）写出来 |
| 常见错法 | 开关看起来已生效其实要另点保存；改了没有历史、无法回滚；高风险项和普通项一个样式；不说明影响范围 |

## P-06 审批 / 审核队列

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 这一条通过、拒绝还是需要更多信息；按什么顺序处理 |
| 布局 | 队列视图默认只显示待处理，默认先进先出（提交时间从早到晚，等得最久的在最前；有优先级时先按优先级）；左列表右详情（或列表 + 抽屉），处理完自动跳到下一条 |
| 组件 / 模式 | 「待处理 / 已通过 / 已拒绝 / 全部」用页签并带计数；通过 / 拒绝是主动作，拒绝必须填原因；版本更新类的审核显示与上一版的差异 |
| 必须有的状态 | 队列清空的空态（「都处理完了」而不是「暂无数据」）；他人已处理的冲突提示；批量通过有影响条数 |
| 常见错法 | 按创建时间倒序，最早的提交沉到最后一页；审核要点进详情页再返回列表，来回跳；拒绝不留原因；看不到提交者和历史；待处理和全部混在一张表 |

## P-07 监控 / 日志 / 排障

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 有没有问题、问题在哪、影响了谁、要不要处置 |
| 布局 | 注意力漏斗：总览 → 排行 → 实体详情 → 异常归因 → 单条回放，每层都能往下一层点 |
| 组件 / 模式 | 时间范围和口径在页头并进 URL；错误按归因（我方 / 上游 / 用户）区分；单条记录一个 URL，能按完整 ID 直接打开 |
| 必须有的状态 | 冷查询慢时显示进度和已用时间；有上限的读取写出上限；默认排除的数据（如用户侧错误）写出「已排除 N 条」 |
| 处置动作 | 断开、清理、取消在途这类动作写出影响条数和是否可恢复，结果写实际处理数 |
| 常见错法 | 只有一张大表没有聚合；统计数字点不进记录或点进去丢了口径；错误只能删除不能标记已处理；默认口径不可见 |

## P-08 计费 / 用量 / 对账

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 钱和额度对不对；某个用户 / 工作区为什么扣了这么多；要不要补偿、退款、调额 |
| 布局 | 先汇总（周期内金额、额度余量、异常）再明细；明细能按用户、模型、渠道、时间切 |
| 组件 / 模式 | 金额右对齐、带币种和精度；估算值标「≈」且不算环比；状态（已支付、退款、争议）用状态标签；调额、退款、发放额度用表单 + 确认，写出前后值 |
| 必须有的状态 | 数据延迟（按天聚合、汇率）写出来；调额 / 退款结果写出新余额；失败不能显示成 0 元 |
| 常见错法 | 金额左对齐、精度不一；估算当精确；钱相关写操作一键完成没有前后对比；看不到操作人和原因 |

## P-09 评测 / 实验对比

场景限定：训练、评测、实验平台这类控制台，对象是「一批用例在某个配置下的一次运行」，用户要比较运行、读分数、找失败原因。其他产品不套用本节；通用的比较规则见 [craft.md](craft.md) K-11。

| 项 | 内容 |
| --- | --- |
| 用户在决定 | 候选比基线好还是差、好在哪坏在哪；失败集中在哪类用例；正在跑的运行还要多久、结果能不能信 |
| 第一屏优先级 | 1. 最新运行的状态与进度（运行中写预计结束和已用时间）2. 主分数 + 与基线的差值 3. 用例结果分布 4. 失败用例入口 |
| 层级与导航 | 项目 → 实验 → 尝试 → 运行 → 任务 → 用例，每层一个固定图标；面包屑每段可回，末段打开同级切换器（按名称或 ID 搜）；ID 用可读名称显示（实验按参数组合，运行按开始时间 + 短哈希），完整 ID 在提示里，复制 ID 是菜单里的明确动作 |
| 必须有的状态 | 运行中 / 已完成 / 失败 / 中断 / 停滞（长时间没有新事件）分开；总数未知时进度标为「至少」；比较两边有新增或移除的用例时单独计数 |
| 常见错法 | 只给分数不给基线；把最佳一次当代表；用例结果的表达每页不同（这里是饼图、那里是数字）；进度在总数未知时画成确定百分比；停掉的运行一直显示「运行中」；只能看汇总，点不进失败用例和它的证据 |

场景 → 可视化 / 交互：

| 场景 | 推荐 | 注意 |
| --- | --- | --- |
| 一组用例的结果（卡片、列表行、表头） | 一条细的堆叠计数条（通过 / 失败 / 运行中 / 其他），全站唯一的结果指示；数字悬停可见：卡片上浮在条上方，行内用提示 | 条旁不再重复写数字；极窄的段也要能读到数；可访问名带精确数，大数用紧凑写法时提示里给精确值 |
| 参数矩阵（模型 × 重复次数 × 场景） | 网格：行取取值最多的那个参数，列取其余组合；每格是该组合最新一次运行的分数、计数条和「较上一次」的差值 | 轴值按语义排序（数字按数值），不按到达顺序；只有一个取值的参数写进列标题，单列也说得清是什么；少于两次运行不显示差值 |
| 比较两个以上的运行或实验 | 每列一张同构卡片（分数、状态、名称、计数条位置固定）+ 分数和通过率的柱状对比 + 用例 × 列的表格，带「只看不同」和差异行标记 | 用例按稳定的用例 ID 对齐；只在一边出现的用例另列；「通过率」和「精确分」是两个口径，分开画 |
| 按类别看回归 | 每个类别一行的差值条或带正负号的差值徽标，正负用固定语义色；总分写「当前值 · 从 X · ±Y」 | 页脚写对齐方式和「新增 / 移除另计」；类别样本少时标样本量 |
| 找失败原因（哪些指标把失败和通过分开） | 按选中的维度数换图：一维是点带，二维是散点 / 分类带 / 分类网格，三维以上是平行坐标加前几个指标的散点矩阵；状态是颜色，不占维度；默认选最能区分失败与通过的几个指标 | 这是专家视图：默认选择就要给出答案；高度相关、恒定、重复的指标折叠并说明为什么隐藏；指标很多时先用相关热力图概览，点格子再看那一对的散点；手机上改为点选后在底部抽屉看卡片 |
| 从图表下钻到用例 | 在轴上拖动、在散点里框选、点分类值，都筛选下方的用例列表；悬停预览，点击固定；固定卡片只列这个用例最反常的指标（离中位数最远），每个配小直方图标出它的位置，其余折叠 | 选区要能一眼看出并能清除；换一个用例时卡片回到折叠状态 |
| 跟进运行中的运行 | 进度条 + 进度曲线：实线是已完成，虚线按当前速率投影到预计结束，总数只是下限时虚线变淡；写预计结束时刻、已用时间、近期速率；「跳到当前」直达正在跑的用例 | 新事件到达时原地更新，不整页重刷；长时间无事件改标「停滞」 |
| 一个用例怎么跑的 | 执行树（运行 → 任务 → 轮次 → 用例 → 重试）带状态筛选和搜索；用例页用时间线区分「整轮重跑」和「单例重试」 | 节点多时虚拟滚动；重试和重跑在计数里分开，不合并成「次数」 |
| 一个用例的证据 | 输入 / 输出用可折叠的对象树；截图序列用带滑块、缩略条和左右键的播放器；日志和逐行记录用分页表格并能按用例定位；所有产物走同一个查看器 | 不能预览的类型写类型和大小并给下载；外部内容只读、隔离展示 |

## 原型之间的通用约束

- 原型只决定优先级和必要状态，具体组件仍走 [components.md](components.md) 的决策表。
- 一个页面横跨两种原型时，按阶段 00 简报里的主任务决定谁在第一屏。
- 每种原型的「常见错法」可以直接作为阶段 04 的检查项。
