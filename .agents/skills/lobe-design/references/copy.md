# copy.md — 微文案规则（W-）

<!-- refs:meta

文案依附在某个决定或状态上。W-01..W-03、W-07 归 40（flow），W-04..W-06 归 70（detail）。

分工：W- 规定**有没有、讲没讲到**（编号与归属不变）；**怎么说、怎么排**（语气、人称、术语、中文排版、按产品类型的措辞）归 75-copy，见 [copy-core.md](copy-core.md) 的 T-01..T-09 与对应 profile。W 条目里的例句只示范要素，最终措辞以 75 选中的 profile 为准。

## W-01 动作文案

- 按钮用「动词 + 对象」：「删除 3 个密钥」「保存配置」，而不是「确定」「提交」「OK」。
- 一屏只有一个 primary，它对应 brief 的主任务。
- 危险操作的确认按钮复述动作本身（「删除」），不要软化成「清除」「重置」；取消按钮写「取消」或「保留」。
- lint：`LOBE-VAGUE-BUTTON`（WARN）检测按钮文字是否为「确定 / 提交 / OK / Submit / Confirm」。

## W-02 标题与说明

- 页面标题和侧栏入口同名。
- 说明用陈述句，讲清「这里能做什么」或「这个数字的口径」，不复述标题，也不写营销腔（「轻松管理」「一站式」）。
- 列名需要解释时用 `TitleWithTips`（C-09），不要在列名后面加括号写长说明。

## W-03 专名与口径一致

- 同一个对象在侧栏、标题、表格列、toast、确认框里用同一个词。
- 状态词和数字一致：显示「3 个失败」时，筛选「失败」后应该正好是 3 条。
- 时间窗和口径写在指标旁边（「近 7 天」「按 UTC」）。

## W-04 空态文案

- 区分三种空：首次使用（引导第一个动作）、筛选后无结果（给出清除筛选）、确实没有（说明为什么）。
- 「暂无数据」不能单独出现，必须带下一步或原因。lint：`LOBE-BARE-EMPTY`（WARN）。

## W-05 错误文案

- 说清发生了什么、为什么、怎么办三件事里至少两件。
- 禁止单独出现「操作失败」「出错了」「Something went wrong」。lint：`LOBE-VAGUE-ERROR`（WARN）。
- 不暴露堆栈和内部错误码；需要错误码时放在可复制的次要位置。

## W-06 确认与占位

- 确认文案写清后果：「关闭后该资产将不再受保护」，而不是「确定吗？」。
- 输入框 placeholder 是示例而不是标签，标签必须单独存在。
- 空值占位全站统一用 `--`（两个连字符）。`—`（长横线）、`–`、单个 `-`、`N/A`、`null`、空白都不是空值占位；`0` 是测到的数，不能当空值。lint：`LOBE-NULLISH-RENDER`（WARN）。

## W-07 简化判据（吸收 Impeccable distill）

对每个字段、按钮、步骤、确认框问一句：**它服务 brief 的哪个决定？**

- 说不出 → 删掉，或降级到详情 / 折叠区 / 更多菜单。
- 两个按钮做同一件事 → 合并。
- 确认框保护的是可撤回的操作 → 改为执行后提供撤销。
- 步骤超过 3 步且中间步骤没有决定 → 合并步骤。
- 不工作的东西直接删：没接数据的占位图、切换后画面不变的控件、同一个数在页面上重复出现。不要为了「看起来完整」留着，也不要为了让它有用去补一个没人要的变体。
- 把删掉的东西列在 40 的输出里，并写明理由，方便回滚。
