> 75-copy 的依据。只管**产品内界面文案**：按钮、标签、标题、空 / 错 / 加载态、确认框、toast、tooltip、表单说明、通知。
> 长篇文档（文档站正文、API 参考、操作手册、Runbook、更新日志、营销长文）**不在范围内**，参照 [Tech-Doc-Style-Chinese](https://github.com/Fenng/Tech-Doc-Style-Chinese)（MIT，作者 Fenng）。本文件的排版与术语部分改写自它，按界面短文案的场景做了取舍。
> 分工：W-（copy.md）规定**有没有、讲没讲到**（动作文案、空 / 错态要素、确认后果）；T-（本文件 + 一份 profile）规定**怎么说、怎么排**。

标注：**〔zh-CN〕** 只适用于简体中文界面；**〔通用〕** 对任何语言都成立。

## T-01 范围与优先级〔通用〕

- 范围：上面列出的界面文案。代码字面量、字段名、枚举值、URL、路径、命令、模型 id、环境变量不改写。
- 冲突时的顺序：① 事实、限制、风险、法律含义 → ② 项目约定（`.agents/ux/product.md`、术语表、品牌规范）→ ③ 术语准确 → ④ 清晰、可扫读 → ⑤ 标点与留白。
- 不补造事实：不新增原文没有的数字、时限、SLA、能力、因果关系；不把「可能」「通常」改成确定语气。信息不够时写「待确认」并列进输出，不自己编。

## T-02 中西文留白〔zh-CN〕

- 中文与英文单词、缩写、阿拉伯数字之间加一个半角空格：`使用 API 获取数据`、`已选 3 项`、`版本 2.0 已发布`。
- 全角标点两侧不加空格：`保存成功，3 秒后跳转`。`%` `°` 紧贴数字：`增长 50%`。
- 插值同样适用：`已选 {{count}} 项`，不写 `已选{{count}}项`。
- 产品名、品牌名按官方写法（官方写法里没有空格就不加）。
- lint：`LOBE-CJK-LATIN-SPACE`（WARN，只看含中文的字符串字面量、JSX 文本和 zh-CN 语言包）。

## T-03 标点〔zh-CN〕

- 中文句子用全角标点：`，。：；？！（）`。中文之间不夹半角 `,` `:` `;` `!` `?`。lint：`LOBE-HALFWIDTH-PUNCT`（WARN）。
- 按钮、标签、菜单、标题、列名、单个短语的 toast **不加句末标点**；说明、帮助、错误详情等完整句子加句号。同一组件里保持一致。
- 指代界面元素用「」：`点击「保存」`。项目已约定用 “” 时服从项目。
- 省略：加载 / 截断用 `…`（U+2026，一个字符），不用 `...`；长句里的省略用 `……`。
- 感叹号只给真正的庆祝时刻，一条文案最多一个；后台和开发者界面不用。

## T-04 数字、单位与时间〔zh-CN〕

- 数字与半角单位符号之间加空格：`10 GB`、`200 ms`；中文量词同样留白：`3 个`、`12 条`。
- 数值精度、单位不擅自换算；百分比与百分点分清（「提升 5 个百分点」≠「提升 5%」）。
- 日期：叙述里写 `2026 年 9 月 29 日`；表格和日志里用 `2026-09-29 15:30`，同一页只用一种。跨时区产品写明时区。
- 范围：句子里用 `3 至 5 天`，表格和筛选里用 `3–5`。
- 空值占位见 W-06（统一 `--`），这里不重复。

## T-05 术语与专名〔通用〕

- 同一概念一个首选词（跨界面一致见 W-03；这里管**选哪个词、怎么写**）。首选词来自项目术语表，没有就在输出里列一张。
- 技术术语和产品名保留原样，不硬译：`API`、`ID`、`URL`、`Token`、`Webhook`、`GitHub`、`OpenAI`。大小写按官方：`JavaScript`、`Node.js`、`PostgreSQL`、`gRPC`。
- 机器可读值在界面上原样展示，必要时用等宽 / 代码样式：`OPENAI_API_KEY`、`gpt-4o-mini`、`/v1/chat`。
- 状态词按语义翻译，不机械对应：

| 英文 | 推荐 | 避免 |
| --- | --- | --- |
| Invalid | 格式有误 / 无效 | 非法 |
| Unauthorized | 未登录 / 登录已过期 | 未授权（它说的是认证） |
| Forbidden | 无权限访问 | 禁止 |
| Not Found | 未找到 <对象> | 404 / 找不到页面了 |
| Pending | 待处理 / 处理中 / 待审核（看语义） | 挂起 |
| Conflict | <对象> 已被修改，请刷新后重试 | 冲突 |
| Timeout | 请求超时 | 超时了 |

- 「登录」不写「登陆」；「账号」「帐号」项目内统一一个。

## T-06 句式〔通用〕

- 动词开头、主动语态、一句一个意思。先结果，后原因，再给动作：`未保存：网络已断开。恢复后点「重试」`。
- 不写黑话和空话：赋能、闭环、打通、抓手、一站式、轻松、极致、海量。只有业务里有明确定义时才用，并写出它指什么。
- 不用双重否定；否定范围要清楚（`不会删除已发布的版本` 而不是 `不能不保留版本`）。
- 指代可能不清时，写对象名而不是「该」「其」「此」。

## T-07 人称与称呼〔zh-CN〕

- 三种选择：无主语（默认）/ 你 / 您。**一个产品选一种**，记在 `product.md` 的文案 profile 里；同一界面不混用。
- 系统不自称「我们」「小助手」，除非 consumer profile 明确允许品牌人格。
- 不责怪用户：`手机号格式有误` 而不是 `你输错了手机号`。

## T-08 i18n 键值卫生〔通用〕

- 不拼接句子（`t('delete') + count + t('items')`）；整句进一个 key，用命名参数：`已删除 {{count}} 项`。长度变化见 X-2.6。
- 复数与量词走 i18n 库的计数形式；zh-CN 可以只写一种，en 必须有 `one` / `other`。
- key 用语义命名（`apiKey.delete.confirmTitle`），不用中文原文当 key；同一含义不同语境用不同 key，不复用「确定」。
- zh-CN 与 en 的插值参数名、数量一致；值里不带首尾空格，不在 key 外面补标点或空格。
- 项目有 i18n 时，组件里不硬编码中文；默认语言包是事实来源，其他语言跟着改。

## T-09 en 简注〔en〕

T-02..T-04、T-07 只对 zh-CN 成立。en 界面另有几条：

- 按钮、标题用 sentence case（`Create API key`，不是 `Create API Key`，专名除外）。
- 半角标点；短标签不加句号；不用 `Please` 开头堆礼貌。
- 先保证 zh-CN 准确，再写 en；不从中文逐字回译（「暂无数据」→ `No API keys yet`，不是 `No data temporarily`）。
