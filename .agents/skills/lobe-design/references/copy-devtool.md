> 只在 75-copy 选中 `devtool` 时加载。通用规则（T-01..T-09）照常适用。这是最接近技术文档的界面，Tech-Doc-Style-Chinese 的规则在这里适用得最完整；文档站正文仍然不在 75 的范围内。

## T-40 语气、人称与密度

- 人称：**无主语**；必要时写明角色（开发者、项目所有者）。不用「您」，也不要客套。
- 语气：精确、技术、可执行。每句话都能回答「是什么 / 限制是什么 / 下一步做什么」之一。
- 密度：可以高，但数字一定带单位和上限：`每分钟最多 60 次请求`，不写 `请求频率有限制`。

## T-41 标识符与代码

- 标识符原样展示并可复制：key 前缀、模型 id、环境变量、HTTP 方法与路径。不要把 `POST /v1/chat` 写成「发送聊天接口」。
- 状态码和错误码保留原文，放在中文说明之后：`认证未通过（401）：API Key 已失效`。
- 命令和配置片段用代码样式，界面不翻译参数名。

## T-42 空态、错误与确认

| 场景 | 推荐 | 避免 |
| --- | --- | --- |
| 首次空态 | `还没有 API Key。创建一个以调用 /v1 接口` + 「创建 API Key」 | `暂无数据` |
| 密钥创建 | `请立即复制，关闭后将无法再次查看完整密钥` | `创建成功！` |
| 请求错误 | `请求参数有误：model 不能为空。查看 请求 ID req_8f2c` | `Bad Request` / `非法请求` |
| 限流 | `已达到速率限制（60 次 / 分钟），12 秒后可重试` | `操作太频繁` |
| 危险确认 | `删除 API Key「prod-server」？使用它的服务将立即无法调用` · 输入 key 名确认 · 按钮「删除 API Key」 | `确定删除？` |

- 错误文案顺序：发生了什么 → 哪个对象 → 可能原因 → 恢复操作 → 诊断信息（请求 ID、时间）。原因不确定时写「可能」，不写成定论（T-01）。

## T-43 表单说明与默认值

- 每个参数写清类型、单位、默认值、范围：`超时（秒）· 默认 30 · 1–600`。
- 不写「根据需要填写」「相关配置」这类无法执行的说明。
