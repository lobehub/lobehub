# Agent 邮箱基础交互规格

> 状态：v1，作为「Agent 邮箱基础交互体验对标成熟邮箱产品」后续任务的唯一依据。
> 基线：`origin/canary` @ `013dd6b01a9`，列表 / 详情分栏 PR #22690（`884e28ecbb8`）已合入。
> 对象：路由 `src/routes/(main)/agent/mail`（`mail/:messageId?`，见 `src/spa/router/agentPageRoutes.tsx:88`），功能目录 `src/features/AgentMail`。
> 依据：`.agents/ux/product.md`、`.agents/ux/components.md`、`ux` skill（Read / Edit / Act / Feedback / Grow）、`lobe-design` 40-flow（L1–L6）、`hotkey` skill。
> 本文只定义行为，不改代码。

**视觉声明：** Gmail / Outlook 只作为交互模式的参照。界面一律使用 LobeHub 自己的视觉语言（`DESIGN.md` token、`@lobehub/ui` 组件、现有 `AgentMail` 分栏结构），不复刻任何产品的外观、布局比例、配色或图标。

## 1. 定位与边界（L1）

**一句话：** 让人在产品内替 Agent 打理它的邮箱：看到收到了什么，代它写信回信，把邮件整理干净。

**页面类型：** P-02 列表 + P-03 详情，消费级密度，文案按 consumer profile，人称用「你」。

**主任务优先级：** ① 看新邮件（含验证码类急件） ② 回复 / 写信 ③ 整理（星标、已读、删除）。

### 1.1 明确不做

| 不做                       | 说明                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 标签 / 分类 / 自定义文件夹 | 只有第 2 节的固定视图                                              |
| 过滤规则 / 自动分拣        | 现有 mail wake 的发件人规则不属于此项，保持原样                    |
| 延迟发送                   | 含「撤销发送」：它的实现就是延迟发送，见 4.6                       |
| 定时发送                   | 不做                                                               |
| 签名                       | 不做                                                               |
| 外部账号接入               | 只管理 Agent 自己的 lobe.id 地址，不接 Gmail / Outlook / IMAP 账号 |

### 1.2 本轮暂缓（不阻塞本目标）

写信时上传新附件。服务端 lobe.id 接口支持，但 LobeHub 客户端尚未接入，且需要上传链路。转发时带上原附件属于本轮（C-05）。

### 1.3 对象模型（统一用词）

| 概念     | 定义                                                                | 界面叫法                 |
| -------- | ------------------------------------------------------------------- | ------------------------ |
| 地址     | 一条 `agent_accounts`（kind = mail）                                | 地址                     |
| 邮件     | 一条 `agent_mails`；收到的邮件另有一条 `agent_inbox_messages`       | 邮件                     |
| 会话     | 同一地址下相同 `thread_key` 的邮件；`thread_key` 为空则自成一个会话 | 不起名字，只显示「3 封」 |
| 邮箱状态 | 未读、星标、垃圾箱，归属**这个 Agent 的邮箱**，不按人区分           | 未读 / 星标 / 垃圾箱     |

「线程 thread」是 Channel 的专名，「话题 topic」是对话实体（`product.md`），邮件界面都不使用。

## 2. 信息架构（L2）

### 2.1 区域

```
┌ 列表栏（沿用 384px）────────┬ 详情栏 ────────────────────┐
│ 页头：邮件      [写信]      │ 工具栏（回复 / 回复全部 / …）│
│ 地址卡（切换 / 更多）       │ 会话正文                    │
│ 视图：收件箱 已发送 草稿 星标 垃圾箱 │ 行内回复框          │
│ 搜索框                      │                             │
│ 列表（或批量工具栏 + 列表） │                             │
└─────────────────────────────┴─────────────────────────────┘
```

### 2.2 视图导航：方案取舍

| 方案                    | 结论     | 理由                                                       |
| ----------------------- | -------- | ---------------------------------------------------------- |
| A. 列表栏内一行视图页签 | **采用** | 不新增栏，保留 #22690 的分栏；5 项都一眼可见，切换一次点击 |
| B. 新增竖向文件夹栏     | 否决     | 5 个固定项撑不起一栏，详情栏被压缩，窄屏还要再折叠一层     |
| C. 下拉选择当前文件夹   | 否决     | 已发送 / 草稿 / 垃圾箱被藏起，入口可发现性差               |

页签放不下时（长语言）横向滚动，当前项保持可见。收件箱显示未读数，草稿显示总数，其余不显示数字；数字按 `ux` 的数字格式化规则进位。

### 2.3 视图定义

| ID   | 视图   | 内容                                    | 排序             | 列表行主字段                 |
| ---- | ------ | --------------------------------------- | ---------------- | ---------------------------- |
| IA-1 | 收件箱 | 收到的、未进垃圾箱的会话                | 最新一封时间倒序 | 发件人                       |
| IA-2 | 已发送 | 含发出邮件的会话，人与 Agent 发出的都算 | 同上             | 收件人                       |
| IA-3 | 草稿   | 未发送的草稿                            | 更新时间倒序     | 收件人，空则「（无收件人）」 |
| IA-4 | 垃圾箱 | 已移入垃圾箱、30 天内的邮件             | 移入时间倒序     | 发件人 + 剩余天数            |
| IA-5 | 星标   | 视图而非文件夹：有星标且不在垃圾箱      | 最新时间倒序     | 发件人                       |

### 2.4 URL 与状态

- 视图和搜索写入查询参数：`?folder=sent&q=关键词`，缺省为收件箱。刷新、前进后退都能还原。
- 打开的邮件沿用路径 `mail/:messageId`；切换邮件仍用 `replace`（现有 `index.tsx` 的做法），返回键直接离开邮件页。
- 写信 / 续写：`?compose=<draftId>`，新写信在首次落稿后才写入 id。

### 2.5 多地址切换（IA-6）

- 沿用地址卡下拉（`MailboxCard`），列表项增加每个地址的未读数。
- 切换时：保留当前视图；清空搜索和选择；关闭打开的邮件；未发送的内容已自动存为草稿，不打断。
- 只按单个地址查看，不做「全部地址」聚合视图。
- 容量：地址 > 7 个时下拉内提供搜索（M-08）。

### 2.6 内容增长

| 场景           | 处理                                                         |
| -------------- | ------------------------------------------------------------ |
| 邮件 1 万封    | 游标分页，不一次加载（Q-04）                                 |
| 列表内有新邮件 | 不挪动阅读位置；已滚动时顶部出现「N 封新邮件」，点击回到顶部 |
| 会话 100 封    | 默认只展开未读和最后一封，中间折叠成「展开 N 封」            |
| 收件人很多     | 默认显示前 3 个 + 「等 N 人」，点击展开                      |

## 4. 操作行为（L3）

### 4.1 写信（C-01）

1. 入口：列表栏页头主按钮「写信」，页面唯一 primary。
2. 宽屏在详情栏打开编辑区，不开浮窗、不跳页；窄屏全屏（见第 8 节）。
3. 字段：发件地址（默认当前地址，只列可发信地址）、收件人（必填，多个）、抄送 / 密送（默认收起）、主题、正文。
4. 正文是纯文本 + Markdown，发送时走现有 `markdownToHtml` / `markdownToPlainText`，不做富文本工具栏。
5. 发件地址旁常驻说明「对方看到的发件人是这个 Agent 的地址」。ux「显示当前身份」要求。
6. 校验：发送时校验收件人格式，错误标在具体地址上。主题为空时询问「不写主题就发送？」，确认后发送。

### 4.2 回复 / 回复全部（C-02、C-03）

- 在会话最后一封下方行内打开，不离开阅读位置。
- 收件人遵循 lobe.id 回复路由：优先 `Reply-To`，否则发件人；回复全部不包含自己的地址。
- 主题固定为原主题（`Re:` 由服务端加），不可编辑；要改主题请用转发。
- 只回复收到的那一封；回复外发邮件时目标取会话里最后一封收到的邮件。
- 回复必须从收到该邮件的地址发出（服务端 `reply_target_not_owned` 约束），发件地址锁定。

### 4.3 转发（C-05）

- 主题自动加 `Fwd:`，正文引用原文，收件人为空。
- 默认带上原附件，可逐个移除。已过期的附件显示「已过期，不会转发」。
- 作为新邮件发出，不继承原 `thread_key`。

### 4.4 草稿（C-06）

| 项       | 规则                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 触发     | 有任一字段内容后，停止输入 1.5 秒保存到服务端                                                   |
| 本地备份 | 每次输入写入 localStorage，以 `agentId + accountId + draftId/回复目标` 为键，防止断网和崩溃丢稿 |
| 唯一性   | 同一封邮件、同一种回复方式只有一份草稿，再次点回复进入续写                                      |
| 状态     | 编辑区显示「保存中 / 已保存 / 保存失败・重试」，失败时不清内容                                  |
| 离开     | 切换邮件、切换地址、关闭、后退都静默存稿，不弹确认                                              |
| 续写     | 从草稿视图打开，恢复全部字段；回复草稿回到原会话                                                |
| 丢弃     | 不进垃圾箱（与 \[G2] 一致），8 秒内可撤销，超时后真正删除                                       |
| 发送成功 | 删除草稿                                                                                        |

### 4.5 发送状态机

`编辑 → 发送中（按钮锁定，编辑区只读）→ 已发送 | 失败（回到编辑，内容保留）`

- 成功：关闭编辑区，toast「已发送」+「查看」（跳转已发送视图）。
- 用客户端生成的幂等键防止连点发两封。
- 服务商已接受、本地记录失败时仍算发送成功，且不提供重试，否则会发出第二封。此逻辑沿用 `recordSentMail` 的做法。

### 4.6 发送不可撤销

「撤销发送」本质是延迟发送，属于明确不做（参照：Gmail 发送后有 5–30 秒可取消 \[G3]，Outlook 网页版为 5–10 秒的延迟 \[M2]）。规格要求：发送前不加二次确认（主题为空除外），发送后不提供撤销，文案不得出现「撤销发送」。

### 4.7 删除（D-01 \~ D-06）

| 操作                      | 确认方式                                           | 撤销                                              | 失败处理                                               |
| ------------------------- | -------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------ |
| 移入垃圾箱（单个 / 批量） | 不确认                                             | toast 显示 **8 秒**撤销，快捷键 `z`；窗口内可撤销 | 行立即恢复原位，错误 toast +「重试」                   |
| 撤销                      | —                                                  | —                                                 | 失败时 toast「撤销失败，可在垃圾箱里恢复」+ 跳转垃圾箱 |
| 从垃圾箱恢复              | 不确认                                             | toast 8 秒撤销                                    | 同移入                                                 |
| 彻底删除（单个）          | 确认框，按钮「彻底删除」                           | **不可撤销**，文案写明                            | 确认框立即关闭；失败时行恢复，错误 toast +「重试」     |
| 彻底删除（批量）          | 确认框写明数量                                     | 不可撤销                                          | 报告「已删除 N 封，M 封失败」，失败项保持选中可重试    |
| 清空垃圾箱                | 确认框写明总数，并需勾选「我知道无法恢复」后才可点 | 不可撤销                                          | 同批量，确认后后台执行                                 |
| 超过 30 天自动清理        | 无                                                 | 不可撤销                                          | 列表行提前显示「N 天后删除」                           |

- 撤销窗口内服务端**已写入**软删，撤销就是调用恢复，不靠延迟提交，因此关页也不丢状态。批量撤销精确恢复这批 id。
- 作用范围：列表上操作会话时，作用于该会话**当前视图内**的全部邮件；详情内可单独操作一封。
- 删除打开中的邮件后：宽屏打开下一封更早的会话但**不自动标已读**（显示占位，点击才打开，遵循 `MailSplitView` 不自动打开的原则）；窄屏回到列表。
- 彻底删除写墓碑而非删行，见 9.3。

### 4.8 已读 / 未读 / 星标（U-02 \~ U-06）

- 全部乐观更新，列表、详情、未读数同时变化，不等待接口。
- 失败：回滚 + toast 说明 +「重试」，不允许静默回滚（ux Act）。标已读的打开动作失败也归入此类，但不打断阅读。
- 30 秒轮询返回时不得覆盖进行中的乐观状态。
- 入口：行内悬停显示星标和已读切换；星标已设置时常驻。详情工具栏里也有。触屏见第 8 节。

### 4.9 批量（D-05、U-05）

- 进入：行首复选框（宽屏悬停出现，选中后常驻）或 `x`；Shift + 点击选连续范围。
- 选中后，列表顶部搜索框位置替换为批量工具栏：`已选 N 封 · 标为已读 / 未读 · 星标 · 移入垃圾箱 · 取消`。垃圾箱内为 `恢复 · 彻底删除`；草稿内为 `丢弃`。
- 全选只选已加载的行，并出现横条「选择此视图全部 N 封」，覆盖未加载的数据。
- 此视图全选由服务端按「视图 + 时间快照」执行，保证操作期间新到的邮件不被误伤；单次上限 1000 封，超过时提示处理了前 1000 封。按 id 的接口保持现有 200 上限。
- 切换视图、地址或搜索词时清空选择。部分失败必须报告数量。

### 4.10 列表

- 行：未读点、星标、发件人（或收件人）、时间、主题、预览、附件图标、会话封数。沿用现有行结构增补。
- 未读点继续使用现有视觉，不新增颜色语义。
- 手动刷新按钮放在视图行右侧。

### 4.11 搜索（Q-02）

- 服务端搜索，覆盖主题、发件人、收件人、正文，范围是当前地址、除垃圾箱和草稿以外的全部邮件，结果行显示所在视图。
- 输入停止 300ms 查询，回车立即查询；有查询时列表内容保持显示并加细进度，不闪骨架。
- 清空（X 或 `Esc`）回到原视图和原滚动位置。

### 4.12 会话视图（Q-03）

- 同一 `accountId + threadKey` 聚合，时间正序，最新在下；进入时定位到第一封未读，全部已读时定位最后一封。
- 收到和发出的邮件都显示；发出的邮件标明「由 Agent 发送」或「由你发送」。
- 打开会话只把当前视图中实际展开的邮件标已读。
- 正文为已去除引用历史的纯文本（`agent_mails.text`），HTML 见 4.14。

### 4.13 分页（Q-04）

沿用现有游标分页和「加载更早的邮件」。不改页码式：新邮件持续到达时页码会漂移。改为会话后，游标取会话最新邮件的 `(receivedAt, id)`。每个视图和搜索结果都用同样方式；加载失败在列表底部重试，已加载内容不动。

### 4.14 HTML 安全渲染（Q-06）

- 服务端按需从服务商取 `html`，经白名单净化后返回，不写入 Agent 上下文（Agent 始终只读纯文本，这是现有注入防线）。
- 前端放进 `sandbox` iframe，**不给** `allow-scripts` 和 `allow-same-origin`；禁止表单、脚本、事件属性、`<base>`、`<meta refresh>`。
- 外部图片默认不加载，顶部提示「已隐藏外部图片・显示图片」，只对当前邮件生效，不做记住。
- 链接新标签打开，带 `rel="noopener noreferrer"`。
- 没有 HTML、已过期或净化失败时回退纯文本，并显示一行说明，不显示空白。

### 4.15 附件（Q-05）

- 经服务端代理下载，走与读取邮件相同的归属校验，浏览器不直连服务商。
- 只做下载，不做自动预览；可执行类文件下载前提示风险。
- 列表显示附件图标，详情显示文件名、类型图标（`FileIcon`）、大小。
- 服务商有保留期（lobe.id 默认 7 天），字节不存在时显示「已过期」且禁用下载，本地描述保留。

## 6. 权限边界盘点

**总则：本节的校验和配额都是现状约束。规格不要求修改现有的 mail wake、配额和权限校验，后续任务也不得绕过；只允许新增只读查询和界面提示。** 客户端判断只用于提示，最终裁决始终在服务端。

### 6.1 能力判定

现状：`agent_accounts.capabilities.send` 对 lobe.id 地址恒为 `true`（`providers/agentMail.ts:142`）。真正的额度由 lobe.id 服务端判定：**LobeHub 现在无法预先知道一个地址能否发信**。

需要新增一个只读查询（复用 lobe.id `GET /v1/end-users/:id` 的 `dailySendLimit` / `remainingSends`；Provision 时 `endUserId` = agentId），不改变任何判定逻辑：

| 状态            | 判断条件                                                                 | 含义                 |
| --------------- | ------------------------------------------------------------------------ | -------------------- |
| `sendable`      | 状态 active /provisioning，`capabilities.send = true`，限额非 0 且有余量 | 可发信               |
| `receive_only`  | `dailySendLimit = 0`                                                     | 免费额度，只收不发   |
| `not_capable`   | `capabilities.send = false`                                              | 这个地址本身不能发信 |
| `limit_reached` | `remainingSends = 0`                                                     | 今日额度用完         |
| `suspended`     | 账号 `suspended`                                                         | 暂停                 |
| `unknown`       | 查询失败或未完成                                                         | 不拦截，由服务端裁决 |

### 6.2 三类账号

**A. 免费额度（只收不发）**

| 项                            | 定义                                                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 能力                          | 收信、阅读、搜索、星标、已读、删除、恢复、附件下载全部可用                                                  |
| 不能                          | 发出邮件（lobe.id 返回 `402 upgrade_required` 或 `402 end_user_send_disabled`）                             |
| 写信 / 回复 / 回复全部 / 转发 | 入口**保留但禁用**，不隐藏，让用户知道有这个能力                                                            |
| 提示                          | 列表栏页头下方常驻一行（不靠 Tooltip，移动端无悬停）：「这个地址目前只能收信。升级后可发信。」+「查看套餐」 |
| 自部署无套餐                  | 文案改为「这个地址目前只能收信。」，隐藏「查看套餐」                                                        |
| 已有草稿                      | 可查看、编辑、丢弃，发送按钮禁用并显示同一文案                                                              |
| `limit_reached`               | 发送按钮禁用：「今天的发信额度已用完，明天再试。」写信和存稿不受影响                                        |
| `unknown`                     | 入口可用，提交后按下表兜底，不预先警告（ux：能力提示必须等配置解析完成）                                    |

发送失败映射（当前 `LobeMailApiError` 只带 status + message，错误统一成 `Failed to send from…`，需要透传错误码）：

| 上游                           | 文案                                     | 操作               |
| ------------------------------ | ---------------------------------------- | ------------------ |
| 402                            | 这个地址目前只能收信。升级后可发信。     | 查看套餐，草稿保留 |
| 429 单用户限额                 | 今天的发信额度已用完，明天再试。         | 草稿保留           |
| 429 单地址（默认每小时 20 封） | 这个地址发信太频繁，请稍后再试。         | 草稿保留           |
| 403 `end_user_suspended`       | 这个邮箱已被暂停发信，请联系支持。       | 草稿保留           |
| 422 `send_rejected`            | 邮件被拒收，请检查收件人：{原因}         | 回到编辑           |
| 404 / `reply_target_not_owned` | 原邮件已不存在，无法回复。可以改用写信。 | 内容保留           |
| 5xx / 网络                     | 发送失败，邮件没有发出。                 | 重试               |

**B. 已释放地址（`status = revoked`）**

现状：`useMailbox` 过滤掉 revoked，地址不进切换列表；释放时删除服务商侧收件箱并清除凭证；`requireActiveAccount` 拒绝使用。本地 `agent_mails` / `agent_inbox_messages` 保留。

| 项                           | 定义                                                                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 切换列表                     | 不显示（维持现状）                                                                                                                                           |
| 释放确认                     | 维持现有确认框，文案需说明「地址上的邮件将不再可见」                                                                                                         |
| 释放后                       | 切到下一个地址；没有地址时显示 `ProvisionCard`                                                                                                               |
| **现状缺陷**                 | 全部释放后 `current` 为空，`useAgentInbox` 在 `accountId` 缺省时返回所有地址的邮件，已释放地址的历史邮件会显示在开通卡下方。期望：无可用地址时**不渲染列表** |
| 直接打开已释放地址的邮件链接 | 现状会显示正文，同时地址卡回退到另一地址，两边不一致。期望：详情顶部显示「这个地址已释放，邮件只能查看。」，隐藏回复、回复全部、转发、星标、删除；地址卡不变 |
| 写操作                       | 该地址的发送、回复、草稿发送全部禁用；服务端 `requireActiveAccount` 继续兜底                                                                                 |
| 附件和 HTML                  | 服务商已删除：显示「已过期」，HTML 回退纯文本                                                                                                                |
| 未发出的草稿                 | 释放确认框提示「N 封草稿会一并删除」                                                                                                                         |

`suspended` 地址：仍在切换列表，显示状态标签，可读不可发，提示「这个地址已暂停，暂时不能发信。」

**C. 工作区成员**

现状：路由用 `ResourceConfigAccessGate`（默认 `requiredAccess='edit'`），没有编辑权的成员被重定向回 Agent 页，**到不了邮箱页**。因此 `AgentMail` 的 `disabled`（`!usePermission('edit_own_content')`）在此路由上实际恒为 `false`，「只读访客」分支不可达。规格维持此门禁，不放宽。

| 角色                      | 邮箱页                         | 读 / 已读 / 星标 / 垃圾箱 / 草稿 / 发信      | 开通 / 释放地址                                  | 彻底删除 / 清空 |
| ------------------------- | ------------------------------ | -------------------------------------------- | ------------------------------------------------ | --------------- |
| 个人空间所有者            | 可进                           | 可                                           | 可                                               | 可              |
| 成员，对该 Agent 有编辑权 | 可进                           | 可                                           | 可（现有 `assertCanEditAgent` + `agent:update`） | 可              |
| 成员，仅查看 / 使用权     | 重定向，toast 说明原因（现状） | 不可达；接口按下方规则仍受保护               | 403                                              | 403             |
| 非成员 / 他人私有 Agent   | 不可达                         | 接口 404，不泄露存在性（现状 `ownership()`） | 404                                              | 404             |

新增接口的校验（新增，不改动现有接口）：

- 读、已读、星标：沿用 `agentAccountProcedure` + `ownership()`，与现有 `markRead` 同级。
- 发信、草稿、垃圾箱、恢复：至少沿用 `AgentAccountService.send` 的 `assertCanUseAgent`。
- 彻底删除、清空：`assertCanEditAgent`，因为销毁的是团队共享数据。

**共享语义：** 未读、星标、垃圾箱、草稿归 Agent 的邮箱，不按成员区分。批量和清空的确认文案要说明「工作区成员也会看到这次改动」（仅工作区内显示）。发信以 Agent 的地址发出，需记录实际操作人（`sent_by_user_id`）用于「由 XX 发送」。

## 8. 窄屏行为

现状：是否单栏只看 `isMobileSurface()`（移动入口），桌面窗口再窄也保持 384px + 详情的分栏。

**断点：** 按邮箱容器宽度判断，< 768px 进入单栏，移动入口始终单栏。沿用 `mobileDetail` 的覆盖方式：详情盖在列表之上，返回后保留列表滚动位置。

| 项                 | 窄屏行为                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| 分栏               | 列表 → 详情单栏切换，路由不变（`mail/:messageId`）                                                |
| 返回               | 详情 / 编辑区页头左侧返回（`NavHeader`），物理返回和手势等价                                      |
| 视图页签           | 横向滚动，当前项滚入可见                                                                          |
| 搜索               | 列表顶部常驻，获得焦点时隐藏页签                                                                  |
| 写信入口           | 页头右侧图标按钮（带文字标签 `aria-label`），不做悬浮按钮                                         |
| 写信 / 回复 / 转发 | 全屏，有独立历史记录，返回即自动存稿回到来源，不弹确认                                            |
| 详情工具栏         | 底部固定：回复（主）、回复全部、转发、更多（星标、未读、删除）                                    |
| 行内操作           | 不依赖悬停；星标常驻行尾，其余长按或进详情                                                        |
| 批量               | 长按一行进入选择模式，点按增减；页头变「已选 N 封 / 取消」；操作固定在底部，超过 3 个收进「更多」 |
| 撤销 toast         | 底部，避开底部工具栏，8 秒不变                                                                    |
| HTML 正文          | 宽度限制在容器内，宽表格在 iframe 内部横向滚动，页面本身不横向滚动                                |
| 触控目标           | ≥ 44px（`product.md` X-5 / K-07）                                                                 |
| 快捷键             | 窄屏桌面窗口保留，移动入口不注册                                                                  |

## 9. 数据与不变量约束

### 9.1 现状缺口（给后续任务）

| 能力                 | 需要                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 已发送 / 会话        | 读取 `agent_mails`（direction + thread）的列表接口                                                                                          |
| 发信                 | router 新增 send /reply/forward，复用 `AgentAccountService.send`；`AgentAccountOutboundMessage` 扩展 `cc`、`bcc`、`replyAll`、`attachments` |
| 草稿                 | 新表 `agent_mail_drafts`                                                                                                                    |
| 垃圾箱、星标、标未读 | `agent_inbox_messages` 或邮件级新字段，覆盖收发两向                                                                                         |
| 搜索                 | 按需的全文检索接口                                                                                                                          |
| HTML、附件           | 服务端代理 + 净化                                                                                                                           |
| 发信能力             | 6.1 的只读查询                                                                                                                              |

### 9.2 标为未读不能写 `readAt = null`

`readAt` 的语义是「Agent 或用户读过」，并且直接参与唤醒：

- `claimWake` 和 `claimDigest` 只认 `read_at IS NULL`，唤醒成功后才标已读（`packages/database/src/models/agentInbox.ts`）。
- `inbound.ts:260` 把「重复投递且未读」当作上次唤醒失败来重试。
- `AgentInboxService.summary` 把未读数注入 Agent 上下文。

如果标未读清空 `readAt`，延迟摘要的 lease 过期后这封邮件会被再次扫入 digest，Agent 被重复唤醒。

**要求：** 新增独立字段（如 `marked_unread_at`）。界面未读 = `read_at IS NULL OR marked_unread_at IS NOT NULL`；打开或标已读时清除该字段。**Agent 和唤醒链路继续只看 `read_at`。** 面向界面的未读数使用新定义，`summary` 不变。

### 9.3 彻底删除写墓碑

`agent_inbox_messages` 同时承担：唯一投递幂等（`source_unique`）、唤醒预算计数（`account_created_at` / `account_sender_created_at` 索引）、话题外发闸门（`topic_id` 索引）。`agent_mails` 被回复检查和验证码转发检查读取。真删除行会重置唤醒预算、让服务商重试时重新入库并唤醒。

**要求：** 彻底删除清空内容字段（主题、正文、预览、收发件人展示、附件描述），保留行和计量字段并写 `purged_at`；所有界面查询排除它。可选调用 lobe.id `DELETE /v1/messages/:id` 删除服务商副本。发信配额由 lobe.id 账本统计，删除不影响。

### 9.4 垃圾箱对 Agent 的影响

垃圾箱是人的整理动作，只影响界面视图：

- 新邮件到达、唤醒、摘要、等待验证码的逻辑不读垃圾箱字段，行为不变。
- `readInbox` 工具应排除垃圾箱和墓碑，避免 Agent 读到用户已丢弃的内容；`checkThreadReply` 和中继检查**不排除**垃圾箱，安全检查不能被移入垃圾箱绕开。

### 9.5 人发信与 Agent 发信

人工发信走新 mutation，复用 `AgentAccountService.send`（活跃状态、`assertCanUseAgent`、`capabilities.send`）和 lobe.id 全部限额。`serverRuntimes/agentAccount.ts` 中的中继和验证码闸门是防注入的，只作用于 Agent 工具调用，**不删改**。人工发信同样记录到 `agent_mails`，让 Agent 后续读取会话时上下文完整。
