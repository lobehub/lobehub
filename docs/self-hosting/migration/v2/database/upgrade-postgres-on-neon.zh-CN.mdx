在部署 LobeHub v2 前，请先将 Neon PostgreSQL 项目升级到 PostgreSQL 17。Neon 仅在 PostgreSQL 17 上开箱支持 `pg_search` 扩展。
<Callout type={'warning'}>
  **开始前请先确认**：
  - **先备份数据库。** 在 Neon 中使用 [Fork Branch](https://neon.tech/docs/manage/branches#create-a-branch) 创建备份。
  - 仅在你接受迁移风险时继续。LobeHub 不对迁移期间发生的数据丢失或问题负责。
  - 仅在你具备数据库迁移经验时使用本指南。
  - 如需帮助，请在 [Discord](https://discord.com/invite/AYFPHvv2jT) 提问或提交 [GitHub Issue](https://github.com/lobehub/lobe-chat/issues/11707)。
</Callout>

## 选择迁移路径

| 方法 | 适用场景 |
| --- | --- |
| [简易迁移](#简易迁移) | 数据库大小低于 10 GB |
| [完整迁移](#完整迁移) | 大型数据库 |

## 简易迁移

若你满足以下全部条件，请使用此方法：

- 使用 Neon 作为数据库提供商。
- 运行的 PostgreSQL 版本早于 17。
- 数据库大小低于 10 GB。
- 数据库超过免费层配额时，可接受 Neon 的额外费用。

在 LobeHub v2 中，数据库迁移需要 `pg_search` 扩展。请先将数据库升级到 PostgreSQL 17，以避免部署失败。

### 按以下步骤操作

1. 使用 [Fork Branch](https://neon.tech/docs/manage/branches#create-a-branch) 备份数据库。

2. **复制连接字符串。**
复制非连接池（unpooled）连接字符串，以提高导入成功率。

![connection-string](https://github.com/user-attachments/assets/9126999a-a6f2-4d4b-ae68-70631e1657cc)

3. **使用 Neon 内置的 Import Data 功能。**
在 Neon 控制台中打开 Import Data 入口：

![import-data](https://github.com/user-attachments/assets/3b48b842-afb1-4e7c-afdf-b1dc4e4c603e)

4. **粘贴连接字符串并按照 Neon 指引继续操作：**
<Callout type={'warning'}>
  **区域要求**：
  请选择支持 `pg_search` 的 AWS 区域。详见 [Neon pg_search 文档](https://neon.com/docs/extensions/pg_search)。
</Callout>

![import-instructions](https://github.com/user-attachments/assets/806c285b-ce8a-4a68-8405-553f7fae8499)

5. **替换原有 `DATABASE_URL`。**
打开连接设置，选择 `import` 分支，复制其连接字符串，替换原有 `DATABASE_URL` 环境变量，然后重新构建或重启 LobeHub。

重建完成后，请确认数据库迁移已成功完成。

## 完整迁移

若你满足以下全部条件，请使用此方法：

- 使用 Neon 且数据库大小超过 10 GB。
- 具备数据库管理和迁移经验。
- 已安装 PostgreSQL 工具。

<Callout type={'warning'}>
  Neon 不支持 `pg_dumpall`。请改用 `pg_dump`。
</Callout>

若你要使用逻辑复制，请参考 [Neon 官方 PostgreSQL 升级指南](https://neon.com/docs/postgresql/postgres-upgrade)。

1. **导出 LobeHub 数据库。**
 ```bash
 pg_dump -Fc -v -d postgresql://[user]:[password]@[neon_hostname]/[dbname] -f <dump_file_name>
 ```

2. **将导出文件恢复到 PostgreSQL 17 数据库。**
 ```bash
 pg_restore -v -d <neon_database_connection_string> <dump_file_name>
 ```

3. **替换原有 `DATABASE_URL`。**
将 `DATABASE_URL` 环境变量替换为新连接字符串，然后重新构建或重启 LobeHub。

重启完成后，请确认 LobeHub 启动正常，且数据库迁移成功。
