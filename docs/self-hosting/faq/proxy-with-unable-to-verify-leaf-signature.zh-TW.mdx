# 使用代理時遇到 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` 錯誤

## 問題描述

在私有化部署時，使用代理（例如：Surge）進行網路請求可能會遇到證書驗證錯誤。

此時錯誤訊息可能如下：

```bash
[TypeError: fetch failed] {
  cause: [Error: unable to verify the first certificate] {
    code: 'UNABLE_TO_VERIFY_LEAF_SIGNATURE'
  }
}
```

或者是：

```json
{
  "endpoint": "https://api.openai.com/v1",
  "error": {
    "cause": {
      "code": "UNABLE_TO_VERIFY_LEAF_SIGNATURE"
    }
  }
}
```

這個問題通常出現在使用代理伺服器時，代理伺服器使用的自簽名證書或中間人證書不被 Node.js 預設信任。

## 解決方案

要解決這個問題，可以在啟動應用程式時新增環境變數，跳過 Node.js 的證書驗證。具體做法是在啟動命令中加入 `NODE_TLS_REJECT_UNAUTHORIZED=0`。例如：

```bash
NODE_TLS_REJECT_UNAUTHORIZED=0 npm run start
```

或者在 Docker 容器中執行時，可以在 Dockerfile 或者 docker-compose.yml 中設定環境變數：

```dockerfile
# 在 Dockerfile 中
ENV NODE_TLS_REJECT_UNAUTHORIZED=0
```

```yaml
# 在 docker-compose.yml 中
environment:
  - NODE_TLS_REJECT_UNAUTHORIZED=0
```

Docker 執行命令示例：

```bash
docker run -e NODE_TLS_REJECT_UNAUTHORIZED=0 <其他參數> <鏡像名>
```

請注意，這種方法會降低安全性，因為它允許 Node.js 接受未經驗證的證書。因此，僅建議在完全信任網路環境的私有化部署中使用，且需要在解決證書問題後恢復預設的證書驗證設定。

## 更安全的替代方案

如果可能，建議通過以下方法解決證書問題：

1. 確保所有的中間人證書都被正確地安裝在代理伺服器和相應的客戶端上。
2. 使用有效的、由受信任的證書頒發機構簽發的證書替換自簽名或中間人證書。
3. 在程式碼中正確設定證書鏈，確保 Node.js 可以驗證到根證書。

採用這些方法可以在不犧牲安全性的前提下解決證書驗證問題。
