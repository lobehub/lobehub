# 模型服務商

LobeHub 在部署時提供了豐富的模型服務商相關的環境變數，你可以使用這些環境變數輕鬆定義需要在 LobeHub 中開啟的模型服務商。

## OpenAI

### `ENABLED_OPENAI`

- 類型：可選
- 描述：預設啟用 OpenAI 作為模型供應商，當設為 0 時關閉 OpenAI 服務
- 預設值：`1`
- 示例：`0`

### `OPENAI_API_KEY`

- 類型：必選
- 描述：這是你在 OpenAI 帳號頁面申請的 API 密鑰，可以前往 [這裡](https://platform.openai.com/api-keys) 查看
- 預設值：-
- 示例：`sk-xxxxxx...xxxxxx`

### `OPENAI_PROXY_URL`

- 類型：可選
- 描述：如果你手動設定了 OpenAI 接口代理，可以使用此設定項來覆蓋預設的 OpenAI API 請求基礎 URL
- 預設值：`https://api.openai.com/v1`
- 示例：`https://api.chatanywhere.cn` 或 `https://aihubmix.com/v1`

<Callout type={'warning'}>
  請檢查你的代理服務商的請求後綴，有的代理服務商會在請求後綴新增
  `/v1`，有的則不會。如果你在測試時發現 AI 返回的訊息為空，請嘗試新增 `/v1` 後綴後重試。
</Callout>

<Callout type={'info'}>
  是否填寫 `/v1` 跟模型服務商有很大關係，比如 openai 的預設位址是 `api.openai.com/v1`
  。如果你的代理商轉發了 `/v1` 這個接口，那麼直接填 `proxy.com` 即可。 但如果模型服務商是直接轉發了
  `api.openai.com` 域名，那麼你就要自己加上 `/v1` 這個 url。
</Callout>

### `OPENAI_MODEL_LIST`

- 類型：可選
- 描述：用來控制模型列表，使用 `+` 增加一個模型，使用 `-` 來隱藏一個模型，使用 `模型名=展示名<擴充功能設定>` 來自訂模型的展示名，用英文逗號隔開。模型定義語法規則見 [模型列表][model-list]
- 預設值：`-`
- 示例：`+qwen-7b-chat,+glm-6b,-gpt-3.5-turbo,gpt-4-0125-preview=gpt-4-turbo`

上面示例表示增加 `qwen-7b-chat` 和 `glm-6b` 到模型列表，而從列表中刪除 `gpt-3.5-turbo`，並將 `gpt-4-0125-preview` 模型名字展示為 `gpt-4-turbo`。如果你想先禁用所有模型，再啟用指定模型，可以使用 `-all,+gpt-3.5-turbo`，則表示僅啟用 `gpt-3.5-turbo`。

你可以在 [modelProviders](https://github.com/lobehub/lobe-chat/tree/main/src/config/modelProviders) 查找到當前的所有模型名。

## Azure OpenAI

如果你需要使用 Azure OpenAI 來提供模型服務，可以查閱 [使用 Azure OpenAI 部署](/zh/docs/self-hosting/examples/azure-openai) 章節查看詳細步驟，這裡將列舉和 Azure OpenAI 相關的環境變數。

### `AZURE_API_KEY`

- 類型：必選
- 描述：這是你在 Azure OpenAI 帳號頁面申請的 API 密鑰
- 預設值：-
- 示例：`c55168be3874490ef0565d9779ecd5a6`

### `AZURE_ENDPOINT`

- 類型：必選
- 描述：Azure API 位址，從 Azure 門戶檢查資源時，可在 「密鑰和終結點」 部分中找到此值
- 預設值：`-`
- 示例：`https://docs-test-001.openai.azure.com`

### `AZURE_API_VERSION`

- 類型：必選
- 描述：Azure 的 API 版本，遵循 YYYY-MM-DD 格式
- 預設值：`-`
- 示例：`2024-02-01`，查閱 [最新版本](https://docs.microsoft.com/zh-tw/azure/developer/javascript/api-reference/es-modules/azure-sdk/ai-translation/translationconfiguration?view=azure-node-latest#api-version)

### `AZURE_MODEL_LIST`

- 類型：必選
- 描述：用來控制模型列表，使用 `模型名->部署名=展示名` 來自訂模型的展示名，用英文逗號隔開。支援擴充功能能力，其餘語法規則詳見 [模型列表][model-list]
- 預設值：`-`
- 示例：`gpt-35-turbo->my-deploy=GPT 3.5 Turbo` 或 `gpt-4-turbo->my-gpt4=GPT 4 Turbo<128000:vision:fc>`

## ComfyUI

### `ENABLED_COMFYUI`

- 類型：可選
- 描述：預設啟用 ComfyUI 作為模型供應商，當設為 0 時關閉 ComfyUI 服務
- 預設值：`1`
- 示例：`0`

### `COMFYUI_BASE_URL`

- 類型：可選
- 描述：ComfyUI 服務的基礎 URL 位址
- 預設值：`http://localhost:8000`
- 示例：`http://192.168.1.100:8000` 或 `https://my-comfyui-server.com`

### `COMFYUI_AUTH_TYPE`

- 類型：可選
- 描述：ComfyUI 的認證類型，支援 4 種認證方式
  - `none`: 無認證（預設）
  - `basic`: 基礎認證（使用者名稱 + 密碼）
  - `bearer`: Bearer Token 認證（API 密鑰）
  - `custom`: 自訂請求頭認證
- 預設值：`none`
- 示例：`basic`

### `COMFYUI_API_KEY`

- 類型：可選
- 描述：當認證類型為 `bearer` 時使用的 API 密鑰
- 預設值：-
- 示例：`sk-xxxxxx...xxxxxx`

### `COMFYUI_USERNAME`

- 類型：可選
- 描述：當認證類型為 `basic` 時使用的使用者名稱
- 預設值：-
- 示例：`admin`

### `COMFYUI_PASSWORD`

- 類型：可選
- 描述：當認證類型為 `basic` 時使用的密碼
- 預設值：-
- 示例：`password123`

### `COMFYUI_CUSTOM_HEADERS`

- 類型：可選
- 描述：當認證類型為 `custom` 時使用的自訂請求頭，需要使用 JSON 格式字符串
- 預設值：-
- 示例：`{"X-Auth-Token": "your-token", "X-Custom-Header": "value"}`

<Callout type={'info'}>
  ComfyUI 支援多種認證方式，請根據您的 ComfyUI 服務設定選擇合適的認證類型和相應的認證參數。如果您的 ComfyUI 服務沒有設定認證，可以不設定認證相關的環境變數。
</Callout>
