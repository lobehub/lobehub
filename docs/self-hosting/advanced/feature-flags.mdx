# Feature Flags

In addition to basic environment variable configuration, LobeHub also offers feature flags to control whether a feature is enabled globally, or to enable or disable features for specific user groups or environments as needed.

## Check Your Deployment Version

Flag names and defaults can change between releases. Check the schema at your deployed version, not only the latest `main` branch. [Feature status labels](/docs/usage/feature-status) describe availability; they are not flag names. This guide does not provide an unverified flag for interactive Agent sharing.

## Feature Flags Environment Variable `FEATURE_FLAGS`

- Type: Optional
- Description: Used to control LobeHub's feature functionalities. Supports multiple feature flags, using `+` to add a feature and `-` to disable a feature. Separate multiple feature flags with a comma `,` and enclose the entire value in quotes `"` to avoid parsing errors.
- Default: `-`
- Example: `"-welcome_suggest"`

`FEATURE_FLAGS` controls the Boolean flags listed here. It does not replace service settings, permissions, credentials, or deployment requirements. An enabled flag alone does not guarantee that a feature is available.

You can achieve various feature combinations using the above configuration syntax. All feature flags are Boolean values, enabled with `+` and disabled with `-`.

<Callout type={'tip'}>
  Attention: Unlike the `OPENAI_MODEL_LIST` variable, the `FEATURE_FLAGS` variable does not support
  the `all` keyword. You need to manually control all feature flags (otherwise, they will adopt
  their default values).
</Callout>

## Interactive Agent Sharing: Deployment and Rollout Boundaries

The following behavior is verified against commit `659db0780b263f023019337a48f23e17e77e260d`. Other versions can differ.

The [`agent_share` schema](https://github.com/lobehub/lobehub/blob/659db0780b263f023019337a48f23e17e77e260d/packages/app-config/src/featureFlags/schema.ts) sets the default to `false`. This flag controls rollout for creators, not visitor access to existing shares.

The [server gate](https://github.com/lobehub/lobehub/blob/659db0780b263f023019337a48f23e17e77e260d/apps/server/src/routers/lambda/_helpers/agentShareFeatureGate.ts) applies two separate checks:

1. Deployment support: `ENABLE_BUSINESS_FEATURES` must be `true`. Without it, both creation and visitor access fail with `FORBIDDEN` before the server evaluates the rollout flag.
2. Creator rollout: New or re-enabled shares also require `enableAgentShare === true` for the creator. A false or undefined value fails closed. Array values in runtime configuration identify permitted creators, not visitors.

<Callout type={'warning'}>
  In the verified open-source code, `ENABLE_BUSINESS_FEATURES` is a code constant set to `false`,
  not an environment variable. `FEATURE_FLAGS="+agent_share"` cannot bypass this deployment gate.
  This flag does not enable interactive Agent sharing on a standard self-hosted deployment.
</Callout>

The [business constant](https://github.com/lobehub/lobehub/blob/659db0780b263f023019337a48f23e17e77e260d/packages/business/const/src/index.ts) defines this boundary. This guide does not prescribe a code change to bypass it.

On a supported deployment, removal from the creator rollout does not itself revoke existing shares. Visitors do not need the rollout flag to access or chat through an existing share. Owners can still manage, preview, or revoke existing shares. These operations remain subject to their existing authorization checks.

The [share router](https://github.com/lobehub/lobehub/blob/659db0780b263f023019337a48f23e17e77e260d/apps/server/src/routers/lambda/agentShare.ts) checks the creator gate for `enableShare` and `updateVisibility` to `link`. A change to `private` does not require the rollout flag and blocks visitor access. Thus, disabling `agent_share` is not a substitute for disabling an individual share.

You can always check the [featureFlags](https://github.com/lobehub/lobehub/blob/main/packages/app-config/src/featureFlags/schema.ts) to get the latest list of feature flags.
