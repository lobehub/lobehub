# 設定 S3 儲存服務

LobeHub 在 [很早以前](https://x.com/lobehub/status/1724289575672291782) 就支援了多模態的 AI 會話，其中涉及到圖片上傳給大模型的功能。在客戶端資料庫方案中，圖片檔案直接以二進制資料儲存在瀏覽器 IndexedDB 資料庫，但在伺服端資料庫中這個方案並不可行。因為在 Postgres 中直接儲存檔案類二進制資料會大大浪費寶貴的資料庫儲存空間，並拖慢計算性能。

這塊最佳實踐是使用檔案儲存服務（S3）來儲存圖片檔案，同時 S3 也是檔案上傳 / 知識庫功能所依賴的大容量靜態檔案儲存方案。

<Callout type={'info'}>
  在本文件庫中，S3 所指代的是指相容 S3 儲存方案，即支援 Amazon S3 API 的對象儲存系統，常見例如
  Cloudflare R2 、阿里雲 OSS，可以自部署的 minio 等均支援 S3 相容 API。
</Callout>

## 核心環境變數

<Steps>
  ### `S3_ACCESS_KEY_ID` 與 `S3_SECRET_ACCESS_KEY`

  所有 S3 相容儲存服務都需要的兩個密鑰，用於存取 S3 儲存服務，不詳細展開。

  ### `S3_ENDPOINT`

  儲存桶的請求端點， 注意此處連結不應該包含儲存桶的名稱。

  <Callout type={'warning'}>`S3_ENDPOINT`必須刪除後綴路徑，否則會無法存取所上傳檔案</Callout>

  例如 Cloudflare 為：

  ```shell
  S3_ENDPOINT=https://0b33a03b5c993fd2f453379dc36558e5.r2.cloudflarestorage.com
  ```

  ### `S3_BUCKET` 和 `S3_REGION`

  儲存桶的名稱和區域，`S3_BUCKET` 是必須的，用於指定儲存桶的名稱。 `S3_REGION` 是可選的，用於指定儲存桶的區域，一般來說不需要新增，但某些服務商則需要設定。

  ### `S3_SET_ACL`

  是否在上傳檔案時設定 ACL 為 `public-read`。該選項預設啟用。如果服務商不支援為檔案設定單獨的 ACL（即所有檔案繼承儲存桶的 ACL），啟用此選項可能會導致請求錯誤，將 `S3_SET_ACL` 設定為 `0` 即可關閉。

  ### `S3_ENABLE_PATH_STYLE`

  是否啟用 S3 的 `path-style` 存取模式。此選項預設禁用。如果您的 S3 服務提供商使用 `path-style`，請將 `S3_ENABLE_PATH_STYLE` 設定為 `1` 以啟用它。

  <Callout type={'info'}>
    `path-style` 和 `virtual-host` 在 S3 中是存取 bucket 和 object 的不同方式，URL 的結構和域名解析不太一樣

    假設 S3 服務商的域名是 s3.example.net ，bucket 為 mybucket，object 為 config.env，具體區別如下：

    - path-style : `s3.example.net/mybucket/config.env`
    - virtual-host : `mybucket.s3.example.net/config.env`
  </Callout>

  <Callout type={'tip'}>
    常見的 S3 Cloud 服務商往往預設採用 `virtual-host` 模式，而自部署服務 minio 則預設使用的是 `path-style`。 因此如果你使用了 minio 作為 S3 服務，你需要設定 `S3_ENABLE_PATH_STYLE=1` 。
  </Callout>
</Steps>
