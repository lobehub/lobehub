# 測試指南

LobeHub 的測試策略包括單元測試和端到端 (E2E) 測試。下面是每種測試的詳細說明：

## 單元測試

單元測試用於測試應用程式中的獨立單元（如組件、函數、工具函數等）的功能。我們使用 [vitest][vitest-url] 進行單元測試。

要執行單元測試，可以使用以下命令：

```bash
npm run test
```

這將執行所有的單元測試，並生成測試報告。

我們鼓勵開發者在編寫程式碼時，同時編寫對應的單元測試，以確保程式碼的品質和穩定性。

## 🚧 端到端測試

端到端測試用於測試應用程式在真實環境中的功能和性能。它模擬使用者的真實操作，並驗證應用程式在不同場景下的表現。

在 LobeHub 中，目前暫時沒有整合端到端測試，我們會在後續迭代中逐步引入端到端測試。

## 開發測試

### 1. 單元測試

單元測試是針對應用程式中的最小可測試單元進行的測試，通常是針對函數、組件或模組進行的測試。在 LobeHub 中，我們使用 [vitest][vitest-url] 進行單元測試。

#### 編寫測試用例

在編寫單元測試之前，您需要建立一個與被測試檔案相同的目錄，並將測試檔案命名為 `<filename>.test.ts`。例如，如果要測試 `src/utils/formatDate.ts` 檔案，測試檔案應命名為 `src/utils/formatDate.test.ts`。

在測試檔案中，您可以使用 `describe` 和 `it` 函數來組織和編寫測試用例。`describe` 函數用於建立測試套件，`it` 函數用於編寫具體的測試用例。

```ts
import { formatNumber } from './formatNumber';

describe('formatNumber', () => {
  it('should format number with comma separator', () => {
    const result = formatNumber(1000);
    expect(result).toBe('1,000');
  });

  it('should return the same number if it is less than 1000', () => {
    const result = formatNumber(500);
    expect(result).toBe('500');
  });
});
```

在測試用例中，您可以使用 `expect` 函數來斷言測試結果是否符合預期。`expect` 函數可以與各種匹配器（matchers）一起使用，例如 `toBe`、`toEqual`、`toBeTruthy` 等。

#### 執行單元測試

通過執行以下命令來執行單元測試：

```bash
npm run test
```

這將執行所有的單元測試，並輸出測試結果。

## 測試策略

為了編寫有效的測試用例，您可以考慮以下測試策略：

- **邊界條件測試**：測試輸入的邊界條件，例如最小值、最大值、空值等。
- **異常情況測試**：測試處理異常情況的程式碼，例如錯誤處理、異常情況下的回退等。
- **功能測試**：測試應用程式的各個功能模組是否正常工作，包括使用者交互、資料處理等。
- **相容性測試**：測試應用程式在不同瀏覽器和設備上的相容性。
- **性能測試**：測試應用程式在不同負載下的性能表現，例如回應時間、資源佔用等。

同時，請確保您的測試用例具有良好的覆蓋率，覆蓋到應用程式中的關鍵程式碼和功能。

通過合理編寫和執行單元測試、整合測試和端到端測試，您可以提高應用程式的品質和穩定性，並及時發現和修復潛在的問題。
