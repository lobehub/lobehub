# LobeHub API 版本管理、弃用与变更日志

## 版本管理

- **主版本号在路径中。** 所有公开端点都位于 `/api/v1` 下。`v1` 内的改动保持向后兼容。会破坏现有客户端的改动改为在新的主版本路径下发布，`v1` 与其并存并继续可用。
- **规范即契约。** [`packages/openapi/openapi.yml`](https://github.com/lobehub/lobehub/blob/canary/packages/openapi/openapi.yml) 在每次改动时由路由定义生成，SDK 再由它生成。每个部署都在 `/api/v1/openapi.json` 提供自己的规范；运行旧版本的自托管实例只支持其规范中列出的内容。
- **LobeHub Cloud 跟随 `canary`。** 合并的改动随下一次部署进入 LobeHub Cloud。自托管实例在包含该改动的下一个版本中获得它。

### v1 内的兼容改动

客户端必须能容忍以下改动，它们可能不经通知发生：

- 新增端点、新增可选请求字段、新增查询参数
- 响应中新增字段
- 枚举中新增取值，例如事件类型、状态和错误码。遇到未知取值时，按最接近的已知类别处理（未知错误码按其 HTTP 状态码处理，未知事件直接忽略）
- 新增 Webhook 事件类型，只有订阅后才会投递到端点
- 新增 API Key scope。新 scope 随新端点增加。现有 API Key 的访问权限保持不变；少数高风险 scope（如 `device:operate`）需要显式授予，不包含在完全访问权限中

### 破坏性变更

以下改动不会在 `v1` 内进行：删除或重命名端点、字段或 SDK 方法；修改字段类型；将可选字段改为必填；改变状态码或错误码的含义；要求现有操作使用新的 scope。

错误码只增不减。操作 id 会成为 SDK 方法名（`agents.list`），一经发布便不再变更。

## 弃用

当字段、参数或端点被替代时：

1. 旧形式继续可用，OpenAPI 规范将其标记为 `deprecated: true`。SDK 在类型文档中显示弃用信息。
2. 替代方案连同迁移说明记录在[变更日志](#api-changelog)中。
3. 旧形式只会在新的主版本中移除。

当前的弃用项，自 [#23231](https://github.com/lobehub/lobehub/pull/23231) 发布后生效：

| 已弃用                                                                       | 替代方案                                         |
| ------------------------------------------------------------------------- | -------------------------------------------- |
| 查询参数 `page`、`pageSize`、`offset`                                           | `limit` 和 `cursor`                           |
| 错误响应体中的 `error` 文本                                                        | `code` 和 `message`                           |
| `GET /agent-groups`、`/api-keys`、`/mcp-servers` 上的 `format=array`（旧的裸数组响应） | 分页响应 `{ items, total, hasMore, nextCursor }` |

**兼容规则的例外。**[#23231](https://github.com/lobehub/lobehub/pull/23231) 上线后，`GET /agent-groups`、`GET /api-keys` 和 `GET /mcp-servers` 的默认响应会从数组改为分页对象。这是 `v1` 内的破坏性变更。把这些列表当作数组读取的客户端，需要在该版本发布前发送 `format=array`，或改用分页响应。

## SDK 版本

- SDK 有改动时，`@lobehub/sdk` 会从 `canary` 自动发布到 npm，版本号为 `1.0.<UTC timestamp>`，使用 `latest` 标签。
- [#23246](https://github.com/lobehub/lobehub/pull/23246) 合并后，版本遵循语义化版本并维护 `CHANGELOG.md`：有变更日志条目的版本以 `latest` 发布，其余改动以 `x.y.z-canary.<timestamp>` 发布在 `canary` 标签下。生产环境请固定使用 `latest` 版本。届时，修改了规范却未重新生成 SDK 的 PR 会在 CI 中失败。
- Python SDK `lobehub`（[#23337](https://github.com/lobehub/lobehub/pull/23337)）从 `0.1.0` 起步。

条目按状态分组。**已发布**的条目已合并并上线 LobeHub Cloud；**即将推出**的条目是尚未合并的 PR，正式发布前可能调整。

| ---------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 2026-11-18 | 规范中每个成功响应都有类型化 schema，SDK 返回类型因此是具体的。所有 `DELETE` 都返回 `{ deleted, id }` 或 `{ deleted, count }` | [#23217](https://github.com/lobehub/lobehub/pull/23217) |
| 2026-11-16 | `GET /users/me` 仅在调用方请求时返回 `messageCount`                                                     | [#23119](https://github.com/lobehub/lobehub/pull/23119) |
| 2026-10-30 | `GET /usage` 返回调用方的额度配额                                                                       | [#21933](https://github.com/lobehub/lobehub/pull/21933) |
| 2026-10-22 | `POST /tasks/{id}/runs` 立即运行任务；`GET /tasks/{id}/runs` 列出其运行记录                                 | [#21470](https://github.com/lobehub/lobehub/pull/21470) |
