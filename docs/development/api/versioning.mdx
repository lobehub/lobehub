# LobeHub API Versioning, Deprecation, and Changelog

## Versioning

- **The major version is in the path.** Every public endpoint is under `/api/v1`. Within `v1`, changes are backward compatible. A change that would break existing clients ships under a new major path instead, and `v1` keeps working alongside it.
- **The specification is the contract.** [`packages/openapi/openapi.yml`](https://github.com/lobehub/lobehub/blob/canary/packages/openapi/openapi.yml) is generated from the route definitions on every change, and the SDKs are generated from it. A deployment serves its own spec at `/api/v1/openapi.json`; a self-hosted instance on an older release supports only what its own spec lists.
- **LobeHub Cloud follows `canary`.** A merged change reaches LobeHub Cloud with the next deployment. Self-hosted instances get it with the next release that includes it.

### Compatible Changes Within v1

Clients must tolerate these, and they can happen without notice:

- New endpoints, new optional request fields, new query parameters
- New fields in responses
- New values in enumerations such as event types, statuses, and error codes. Treat an unknown value as its closest known category (an unknown error code by its HTTP status, an unknown event by ignoring it)
- New webhook event types, which reach an endpoint only after you subscribe to them
- New API key scopes. Scopes are added for new endpoints. An existing key keeps exactly the access it had; a few high-risk scopes such as `device:operate` are explicit and are not included in full access

### Breaking Changes

These are not made within `v1`: removing or renaming an endpoint, field, or SDK method; changing a field's type; making an optional field required; changing the meaning of a status code or error code; requiring a new scope for an existing operation.

Error codes are only ever added. Operation ids, which become SDK method names (`agents.list`), do not change once shipped.

## Deprecation

When a field, parameter, or endpoint is replaced:

1. The old form keeps working, and the OpenAPI spec marks it `deprecated: true`. The SDKs show the deprecation in their type documentation.
2. The replacement is documented in the [changelog](#api-changelog) with a migration note.
3. The old form is removed only in a new major version.

Current deprecations, effective when [#23231](https://github.com/lobehub/lobehub/pull/23231) ships:

| Deprecated                                                                                       | Replacement                                                    |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `page`, `pageSize`, `offset` query parameters                                                    | `limit` and `cursor`                                           |
| `error` text in error bodies                                                                     | `code` and `message`                                           |
| `format=array` on `GET /agent-groups`, `/api-keys`, `/mcp-servers` (the old bare-array response) | The paginated `{ items, total, hasMore, nextCursor }` response |

**Exception to the compatibility rule.** When [#23231](https://github.com/lobehub/lobehub/pull/23231) ships, `GET /agent-groups`, `GET /api-keys`, and `GET /mcp-servers` change their default response from a bare array to the paginated object. This is a breaking change inside `v1`. A client that reads these lists as arrays must send `format=array` or move to the paginated response before that release.

## SDK Versions

- `@lobehub/sdk` is published to npm from `canary` automatically when the SDK changes, as `1.0.<UTC timestamp>` under the `latest` tag.
- With [#23246](https://github.com/lobehub/lobehub/pull/23246), releases follow semantic versioning with a `CHANGELOG.md`: versions with a changelog entry are published as `latest`, and every other change as `x.y.z-canary.<timestamp>` under the `canary` tag. Pin `latest` versions in production. A pull request that changes the spec without regenerating the SDK then fails CI.
- The Python SDK `lobehub` ([#23337](https://github.com/lobehub/lobehub/pull/23337)) starts at `0.1.0`.
