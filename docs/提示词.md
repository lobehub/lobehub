# 用量配额与部门统计功能实现计划

## 背景

管理员需要查看每个用户和每个部门的用量统计，并为其设置每日 / 每月的费用和
Token 上限。当用户超出限额时，AI 请求将被拒绝，并在错误提示中显示今日已使用的费用。

## 需求概述

- 管理员统计页：可在 "我的用量 / 按用户 / 按部门" 三种视图间切换
- 管理员可为每个用户或部门设置限额（每日 / 每月费用 + Token）
- 有效限额 = min (用户限额，部门限额)，取更严格的一方
- 两级执行：≥80% → 警告提示，≥100% → 请求被拒绝
- 拒绝时的错误信息包含今日实际已用费用
- 用户侧用量卡片显示配额进度条

---

## 实现步骤

### 步骤 1：数据库迁移

**文件：** `packages/database/src/schemas/user.ts`

- 在 `users` 表中新增 4 个字段：
  - `dailyCostLimit`（每日费用上限）
  - `monthlyCostLimit`（每月费用上限）
  - `dailyTokenLimit`（每日 Token 上限）
  - `monthlyTokenLimit`（每月 Token 上限）

**新文件：** `packages/database/src/schemas/departmentQuota.ts`

- 新建 `department_quotas` 表，主键为 `department`，包含同样的 4 个限额字段

**迁移：** `cd packages/database && bunx drizzle-kit generate`

---

### 步骤 2：配额检查服务

**文件：** `src/server/services/usage/index.ts`

在 `UsageRecordService` 中新增 `checkQuota()` 方法：

1. 查询当前用户的限额及所属部门（`interests[0]`）
2. 查询该部门的限额
3. 取 min (用户限额，部门限额) 作为有效限额
4. 查询今日和本月的费用 + Token 用量
5. 根据 80%/100% 阈值返回状态（ok /warning/exceeded）

---

### 步骤 3：TRPC 路由 — 配额执行 + 管理员 API

**文件：** `src/server/routers/lambda/usage.ts`

新增以下接口：

- `checkQuota` — 已登录用户调用，返回配额状态
- `adminGetAllUserQuotas` — 仅管理员，返回所有用户及其限额
- `adminGetAllDepartmentQuotas` — 仅管理员，返回所有部门配额
- `adminSetUserQuota` — 仅管理员，更新用户限额
- `adminSetDepartmentQuota` — 仅管理员，upsert 部门配额
- `adminGetUsageByDepartment` — 仅管理员，按部门聚合用量
- `adminGetUsageByUser` — 仅管理员，查询指定用户的用量明细
- `adminGetUsageByDepartmentDetail` — 仅管理员，查询指定部门的用量明细

---

### 步骤 4：AI 请求前执行配额检查

**文件：** `src/server/routers/lambda/aiChat.ts`

在向 AI 提供商发送请求前调用 `checkQuota()`。若状态为 `exceeded`，抛出 TRPC FORBIDDEN 错误，携带 JSON payload：

```json
{
  "effectiveDailyCostLimit": 1.0,
  "reason": "quota_exceeded",
  "todayCost": 0.123456
}
```

---

### 步骤 5：客户端服务

**文件：** `src/services/usage.ts`

新增方法：

- `checkQuota()`
- `adminGetAllUserQuotas()`
- `adminGetAllDepartmentQuotas()`
- `adminSetUserQuota(userId, limits)`
- `adminSetDepartmentQuota(department, limits)`
- `adminGetUsageByDepartment(mo?)`
- `adminGetUsageByUser(userId, mo?)`
- `adminGetUsageByDepartmentDetail(department, mo?)`

---

### 步骤 6：管理员统计 UI

**文件：** `src/routes/(main)/settings/stats/index.tsx`

- 将 Segmented 控件扩展为 3 个选项：我的用量 / 按用户 / 按部门

**新组件：** `AdminUserQuotaTable.tsx`

- 表格：邮箱、部门、4 个限额列、"设置限制" 按钮、"查看用量" 按钮
- "设置限制" 打开 Modal，包含 4 个 InputNumber 输入框
- "查看用量" 展开内联详情面板，显示用量卡片 + 趋势图，支持月份切换

**新组件：** `AdminDepartmentQuotaTable.tsx`

- 同上，以部门为维度

---

### 步骤 7：用户侧配额展示

**文件：** `src/routes/(main)/settings/stats/features/usage/UsageCards/`

在 `TodaySpend` / `MonthSpend` 卡片中，若有配额数据：

- 显示进度条：已用 / 上限
- ≥80%：黄色，≥100%：红色

---

### 步骤 8：请求被拒绝时的错误提示

**文件：** `src/features/Conversation/ChatInput/index.tsx`

当 TRPC 错误的 reason 为 `quota_exceeded` 时，显示：

> 今日用量已达上限（已使用 $X.XXXXXX），请明天再试

从错误 JSON 中解析 `todayCost` 并格式化展示。

---

### 步骤 9：国际化（i18n）

**文件：** `src/locales/default/auth.ts`、`locales/zh-CN/auth.json`、`locales/en-US/auth.json`

新增 key：

- `usage.quota.exceeded` — 今日用量已达上限（已使用 ${{cost}}），请明天再试
- `usage.quota.warning` — 用量已达 {{percent}}%，请注意控制使用
- `usage.quota.setLimit` — 设置限制
- `usage.quota.viewUsage` — 查看用量
- `usage.quota.dailyCost` — 每日费用上限（$）
- `usage.quota.monthlyCost` — 每月费用上限（$）
- `usage.quota.dailyTokens` — 每日 Token 上限
- `usage.quota.monthlyTokens` — 每月 Token 上限
- `usage.quota.noLimit` — 无限制
- `usage.view.mine` — 我的用量
- `usage.view.byUser` — 按用户
- `usage.view.byDepartment` — 按部门
