# Using Multiple Model Providers in LobeHub

<Image alt={'Multi-Model Provider Support'} borderless cover src={'/blog/assets17870709/1148639c-2687-4a9c-9950-8ca8672f34b6.webp'} />

You can choose a model provider for each Agent or connect a local inference service. This page groups setup guides by use case. The full provider cards remain at the end.

## Why Multi-Provider Support?

- **One interface** — Select models and modalities that each provider supports.
- **Cost comparison** — Compare task quality, latency, and budget.
- **Less dependence on one vendor** — If a provider becomes unavailable, select a compatible, configured alternative. This does not guarantee automatic failover.
- **Per-Agent choice** — Set different default models for different responsibilities.
- **Local inference** — Run local models with Ollama or LM Studio. Local inference usually avoids cloud model API charges, but hardware and operation still have costs.

A local model does not make the entire workflow private or offline. Cloud sync, search, and other Connectors can still transmit data.

## Setting Up Providers

Open **App Settings → AI Providers**, then select the provider you want to configure. The available fields depend on the provider:

1. Select a provider from the list and turn on its switch.
2. Enter the credentials shown on the page. Most cloud providers use an API key. Providers such as Amazon Bedrock and Azure OpenAI also show region, endpoint, or other provider-specific fields.
3. If **Proxy URL** is available, enter the provider API base URL or a compatible endpoint. For local services, enter the Ollama or vLLM server address.
4. Select **Check** to test the connection.
5. Enable a model in the model list. You can also fetch or add models when those actions are available.
6. Your changes are saved automatically. You can then select the provider and model in the Agent settings.

For environment variable configuration in self-hosted deployments, see the [model provider environment variables](/docs/self-hosting/environment-variables/model-provider) reference.

See the [Agent guide](/docs/usage/getting-started/agent) for model selection principles. See [Feature Status and Availability](/docs/usage/feature-status) for Cloud and Desktop definitions.

## Troubleshooting

**Connection error / API key invalid** — Check your API key for extra spaces. Check that the key type matches the provider.

**Model not available** — Your account tier can exclude a model, or the provider can retire it. Check the provider's model availability page.

**Rate limit errors** — You reached the provider's request rate limit. Reduce the request rate, use another configured provider, or review account upgrade options.
