# 任务

![](https://hub-apac-1.lobeobjects.space/blog/assets4aa1732a45832afc780600e6e329860c.webp)

**任务（Task）** 把你和 Agent 的对话变成可追踪的工作。不必实时聊天再到处复制结果，你可以写下需求、把它指派给一个 Agent，让 Agent 在后台为你完成。Agent 会回报进度、在完成后更新状态，并在你留下评论时继续跟进。

如果你用过 Linear 或 GitHub Issues，思维模型完全一致 —— 只是这里的执行人是 Agent，并且它会真的把活干完。

## 什么时候用任务

当你希望 Agent 做下面这些事情时，就适合开任务：

- 完成耗时超过几分钟的工作。
- 按计划运行（例如每天早上或每周一）。
- 异步反馈进度，让你可以同时处理其他事情。
- 留下完整历史，便于后续重新分配、评论或回溯。

对于一次性的、很快能答完的问题，留在普通对话里就好。任何你原本会记在待办列表或工单里的事情，都建议开一个任务。

## 任务生命周期

任务状态显示工作进度，自动化设置控制执行时间。任务列表使用以下状态：

| 状态 | 含义 |
| --- | --- |
| **Backlog** | 待处理。 |
| **Running** | 正在执行。 |
| **Scheduled** | 等待自动化计划触发。 |
| **Pending review** | 暂停并等待检查或后续处理。 |
| **Completed** | 已完成。 |
| **Failed** | 执行失败，需要查看错误和结果。 |
| **Canceled** | 已取消。 |

运行结束后，查看结果及已配置的验收检查，详见[验收结果](#验收结果)。

## 创建任务

<Steps>
  ### 打开任务面板

  在主界面打开**任务（Tasks）**，可以查看所有 Agent 的任务；在某个 Agent 页面打开**任务（Tasks）**，则只显示当前 Agent 的任务，不显示其他 Agent 的任务。

  ### 新建任务

  在右上角点击 **New Task**。给任务起一个清晰的标题 —— Agent 会根据标题和描述来理解你的意图。

  ### 填写描述

  像给同事派活一样描述工作内容，包含必要的链接、文件或限制条件。你可以像在普通对话里一样粘贴图片、附加 Resource。

  ### 指派 Agent

  如果从主界面创建，在 **Assignee** 下拉框中选择执行任务的 Agent。如果从某个 Agent 页面创建，任务直接归属当前 Agent，无需另选 Agent。

  ### 选择运行方式

  普通任务可按需执行。需要周期执行时，在任务详情的**自动化（Automation）**区域配置**定时（Scheduled）**或**固定间隔**，无需另建一套定时任务。详见[Agent 任务](/zh/docs/usage/agent/scheduled-task)。

  ### 提交

  点击 **Create** 保存任务，再启动执行或启用调度，并检查任务状态。
</Steps>

<Callout type="info">
  启用任务工具后，也可以通过对话请求 Agent 创建任务。打开创建的任务，检查指令是否包含必要背景。
</Callout>

## 与 Agent 协作

当任务进入 **Running** 后，打开任务详情查看进度、工具调用和可用的运行结果。

### 验收结果

打开任务详情，检查产出物、运行记录和验收检查报告。如果结果需要调整，说明缺失项并让 Agent 继续处理；满意后再按界面提供的操作确认完成。

配置验收（Acceptance）后，助理会在交付前检查这些要求。检查未通过时，可以阻止交付并触发修复。报告包含结论、评分及每项检查的证据，可作为你验收结果的参考。

具体配置与示例参见[验收（Acceptance）](/zh/docs/usage/agent/connectors#acceptance)。

### 评论与追问

每个任务都有一条评论线索，可以用来：

- **澄清**：当 Agent 在执行过程中提问时回复它。
- **纠偏**：当 Agent 走偏方向时及时拉回。
- **迭代**：在验收阶段说明需要修改的内容，例如「同样的内容但排除周末」，再检查任务是否已继续执行。

提交评论后，查看 Agent 回复及任务状态，了解工作是否已继续执行。

### 产出物（Artifacts）

在任务详情打开关联产出物，查看研究笔记、摘要或初稿。如果缺少预期交付物，请让 Agent 提供其保存位置。

## 一次性任务 vs. 周期任务

任务支持两种运行方式。

### 一次性执行

不需要重复的工作按需启动。执行后查看结果及任务状态，根据需要追加说明或进行验收。

### 周期执行

从 Agent 页面或主界面的**任务（Tasks）**打开目标任务，再进入**任务详情 → 自动化**配置计划。同一个任务承载自动化配置与运行记录；定时功能不是独立的另一套任务系统。保存配置后，按界面提示启动调度，并核对状态和下次运行时间。

选择**每天、每周或每小时**，小时输入范围为 1–24。需要按时长重复执行时，选择**固定间隔**。定时表单没有每月或自定义 cron 选项。详见[Agent 任务](/zh/docs/usage/agent/scheduled-task)。

![](/blog/assets17983f73d00c4d39dceb9dac0f6fa0ed.webp)

<Callout type="warning">
  重复运行会持续产生模型或工具使用成本。请检查频率、运行次数上限及账户用量。
</Callout>

需要停止后续自动运行并保留任务配置时，关闭自动化。删除任务前，请保存需要的结果，并检查本次删除包含哪些记录。详见[删除任务与关闭自动化](/zh/docs/usage/agent/scheduled-task#删除任务与关闭自动化)。

## 使用示例

下面这些场景特别适合做成任务：

- **每日市场摘要** —— 一个 Research Agent，在每个工作日早上 8 点汇总隔夜资讯。
- **每周竞品扫描** —— 一个 Agent 访问 5 个竞品网站并提示定价变化。
- **一次性深度研究** —— 一个需要较长时间完成的任务（「对比这 12 个向量数据库」），你过一会儿再回来看结果。
- **周期数据拉取** —— 一个 Agent 每周一查询数据库并把结果发到任务里。
- **想法收件箱** —— 把临时灵感丢进任务列表，让 Agent 在夜里准备好初稿，第二天直接修改。
