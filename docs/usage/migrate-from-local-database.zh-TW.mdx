# 從本地資料庫（v1.x）遷移到雲端（v2.x）

在 LobeHub v1.x Desktop 中，我們曾提供 **本地資料庫** 模式，將資料儲存在當前設備上。自 v2.x 起，我們轉向 **Cloud-first 架構** 並移除了本地資料庫能力，以便後續更好、更快地迭代，並在不同平臺上提供更一致的體驗。

<Callout type="info">
  為什麼要這樣做？v1.x
  的本地資料庫通常會帶來更高的資源佔用，而實際使用它的使用者佔比較小。砍掉這條分支能力後，我們可以讓客戶端更輕量、更穩定，同時把更多精力投入到
  Cloud-first 體驗與新功能交付上。
</Callout>

本文會引導你完成：**在 v1.x 導出資料** → **在 v2.x 導入資料**。

## 開始前準備

- 建議在遷移確認完成之前，**不要卸載 v1.x**。
- 準備 **穩定的網路連接**（如果對話記錄較多，導入可能需要更久）。
- 登入 **LobeHub v2.x**（雲端或你的自部署實例）。

如果你希望把 Cloud 部署在自己的伺服器上，也可以先參考 [私有化部署指南](/docs/self-hosting/start) 完成部署，再把資料導入到自部署的 v2.x 實例中。

## 如果你已經不小心升級到了 v2.x

你依然可以完成遷移：

1. 前往 [GitHub Releases](https://github.com/lobehub/lobe-chat/releases) 下載並安裝一個 **v1.x 版本**。
2. 使用 v1.x 按照本文的導出流程導出資料（`Settings -> Data Storage -> Export Data`），再在 v2.x 中導入。

請放心：**升級到 v2.x 的過程不會刪除你的本地資料庫檔案**。只要本地資料庫檔案仍然存在，你的資料就依然存在。

### 本地資料庫檔案位置

本地資料庫預設位於：

- `${appData}/lobehub-storage/lobehub-local-db`

## 通常可以遷移的內容

可遷移內容會受導出格式與 v1.x 構建版本影響，但一般包括：

- 助手 / Agents
- 會話 / Topics 與訊息記錄
- 提示詞模板（如你的 v1.x 版本支援）
- 部分基礎偏好設定（如版本支援）

## 通常不會遷移的內容（常見情況）

- 各模型服務商的 API Key / Secret（更推薦在 v2.x 重新填寫）
- 僅存在於本地的臨時檔案、快取資料
- 一些與設備強綁定的設定項

<Callout type="warning">
  如果你的 v1.x 封包含敏感內容，請妥善保管導出的遷移檔案，避免在公共管道分享。
</Callout>

## 第一步：在 LobeHub v1.x 導出資料

在 v1.x Desktop 客戶端中：

1. 進入 **Settings** → **Data Storage** → **Export Data**。
2. 你會得到一個 JSON 導出檔案（例如：`2026-01-22-10-02_LobeHub-data.json`）。
3. 將導出的檔案儲存到你容易找到的位置（例如桌面）。

![v1.x 導出資料](/blog/assets13656829368732a95940edeff9ddfca6.webp)

### 導出建議

- 如果你的歷史記錄非常多，建議在設備空閒時導出。

## 第二步：在 LobeHub v2.x 導入資料

在任意 v2.x 應用程式中（Desktop / Web / 自部署 WebApp）：

1. 登入你的 LobeHub 帳號。
2. 進入 **Settings** → **Data Storage** → **Import Data**。
3. 上傳你在第一步導出的 JSON 檔案。
4. 等待導入完成；必要時刷新頁面 / 重啟應用程式。

![v2.x 導入資料](/blog/assets1e640c898e897bfb4ce4b66d5377010b.webp)

## 遷移完成後如何驗收

導入完成後，建議你檢查：

- 助手是否齊全，提示詞 / 設定是否正確
- 最近的會話是否能正常開啟、訊息是否完整
- 常用設定（語言、主題、快捷鍵等）是否符合預期

如發現缺失，建議先升級到最新 v2.x 後再重試導入，同時保留 v1.x 的導出檔案用於排查。

## 常見問題排查

### 導入失敗或長時間卡住

- 確認網路穩定後重試。
- 升級到最新 v2.x 再導入一次。

### 導入後部分資料缺失

- 不同 v1.x 構建版本的資料結構可能略有差異。
- 如果你在 v1.x 使用過多個設定 / 空間（若支援），可嘗試分別導出並逐個導入（如版本支援）。

## 獲取幫助

如果你遇到遷移問題，可以查看 [幫助與支援](/docs/usage/help) 或通過 [GitHub Issues](https://github.com/lobehub/lobe-chat/issues/new/choose) 回饋。
