# 连接器

通过连接器，助理可以使用工具、调用技能、访问你授权的服务并执行操作。你可以添加任务管理、文档和图片生成工具，安装社区 Skills 和 MCP，或连接 GitHub、Notion、Google Drive 等第三方服务。

你可以按任务需要添加工具和技能，并选择固定启用、自动使用或禁用。需要访问第三方服务时，先完成账户连接与授权。

## 可以连接什么

| 类型              | 作用                                       | 示例                                         |
| ----------------- | ------------------------------------------ | -------------------------------------------- |
| LobeHub 内置能力  | 在 LobeHub 中管理任务、创作内容和执行操作 | 任务工具、文档、消息、图片生成、Artifacts 等 |
| 第三方服务        | 访问授权账户资源，执行连接器支持的操作     | GitHub、Linear、Gmail、Slack 等              |
| 社区 Skills       | 领域指令、工作流程及配套资源               | 技能商店的 Skills 标签                       |
| 社区 MCP          | 通过 Model Context Protocol 接入工具       | 技能商店的 MCP 标签                          |
| 自己导入的 Skills | 使用自己编写或从其他来源取得的技能         | GitHub、URL、ZIP 导入                        |

可见项目取决于客户端、部署设置、账户权限和执行环境。安装技能不会自动授予第三方账户或本机文件访问权限。

## 如何使用连接器

### 从技能菜单进入

1. 打开 **Agent 页面**。
2. 点击输入框左下角的 **+** 按钮。
3. 选择 **技能**，查看当前助理的固定启用和自动使用列表。
4. 点击 **添加技能…** 进入技能商店；点击 **Skills 市场** 管理已有工具和技能。

商店有 **LobeHub、Skills、MCP** 三个标签：在 LobeHub 中可以找到内置工具和第三方服务连接器，在 Skills 和 MCP 中可以找到社区扩展。右上角「添加」可从 GitHub、URL 或 ZIP 导入技能，也可添加自定义 MCP。

### 添加与授权

1. 找到所需条目，阅读用途、依赖和权限要求。
2. 内置工具按界面添加；第三方服务点击「连接」，完成账户授权。
3. 社区扩展按提示安装，补齐 MCP 端点、认证或脚本执行依赖。
4. 回到当前助理的技能列表，检查使用模式，再发起任务。

**安装、授权、在当前助理中启用是不同步骤。** 连接成功后，仍只能访问已授权的资源。

### 固定、自动与禁用

| 模式           | 含义                                               | 适用情况               |
| -------------- | -------------------------------------------------- | ---------------------- |
| 固定／固定启用 | 设为当前助理的默认加载项，仍受运行环境与权限限制   | 经常使用的工具和技能     |
| 自动           | 允许助理按任务需要发现和激活，不是每次加载全部内容 | 偶尔使用的工具和技能         |
| 禁用           | 当前助理不使用该工具或技能                               | 暂时不需要或不希望使用 |

在条目的操作菜单中选择模式。「自动」分组开关控制自动激活，不是批量安装或卸载。取消固定不等于卸载，禁用不等于撤销账户授权；部分系统工具的选项不同。

接下来直接描述任务，例如「把调研结果保存成文档」或「查找我有权限访问的 GitHub Issue」。涉及发送、修改和删除时，说明目标和允许的范围，检查执行结果。**密码和 API 密钥应通过安全凭据入口提供，不要粘贴到普通对话。**

## LobeHub 内置能力

LobeHub 内置工具可以管理任务、文档和消息，生成图片，执行计算和创作交互内容。你可以在技能商店的 **LobeHub** 标签中选择所需工具；可用项目取决于客户端和执行环境。

<a id="task-tools" />

### 任务工具（Task Tools）

**用途：**通过对话创建和管理任务、子任务、依赖、执行助理、状态和评论。你也可以设置验收要求、开始执行任务，改动会显示在[任务界面](/zh/docs/usage/getting-started/task)中。

**试着说：**「创建新品发布任务，拆成文案、设计和最终检查；最终检查依赖前两个任务完成。」

使用前确认工具与权限可用；创建后检查保存的任务、执行助理、输入和结果要求。如需定期执行，先配置并启用计划，再核对时区、下次执行时间和状态。仅设置截止时间不会触发执行或通知，详见[定时任务](/zh/docs/usage/agent/scheduled-task)。删除前确认目标及子任务范围。

<a id="delivery-checks-and-acceptance" />
<a id="acceptance" />

#### 验收（Acceptance）

验收（Acceptance）帮助你判断产出是否满足要求。配置验收条件后，助理会在交付前逐项检查。检查未通过时，可以阻止交付并启动修复轮次。报告包含结论、评分和每项检查的证据。

建议按以下流程操作：

1. **执行前定义检查项。** 写出可以核验的条件，例如必需章节、来源链接、时间范围，以及产出物能否打开。避免只写「质量要高」。
2. **确认配置已保存。** 请 Agent 添加检查项，再查看任务配置。如果验收检查不可用，就按这些标准人工复核。
3. **运行后检查。** 查看交付物和检查报告，将每项证据与要求对照。
4. **处理未通过项。** 阅读失败原因和修复结果。若仍被阻止交付或修复不足，补充缺失信息或提出修改要求，再检查新结果。
5. **确认验收。** 结果满足要求后，使用当前可用的操作确认完成。人工验收与检查报告是不同环节。

**请求示例：**

> 创建竞品报告任务并添加验收检查：覆盖指定的三家公司；每条价格结论附来源链接和发布日期；写明观察期与币种；无法核实的信息单独列出。执行前先让我检查保存的验收条件。

自动检查只覆盖已配置的要求。即使全部检查通过，重要事实和最终交付物仍需你亲自复核。

<a id="using-the-cli" />

#### 使用 CLI

安装 LobeHub CLI 并登录目标部署后，可通过 `lh task` 操作同一套任务系统：

```bash
lh task list
lh task view T-1
lh task create -i "撰写发布说明"
lh task edit T-1 --status completed
```

将 `T-1` 替换为目标任务标识。标记完成前，先查看交付物和检查报告。最后一条命令只修改状态。可用选项请查看已安装版本的帮助。

<a id="documents" />

### 文档（Documents）

**用途：**创建和维护助理长期保存的文档，适合报告、笔记、项目背景和参考资料。

**启用后可以：**创建、读取、重命名、复制和删除文档；替换全文或精确修改局部；列出文档并调整加载规则。文档可以属于助理，也可以关联当前话题。

**试着说：**「创建一份竞品调研文档，保留来源；以后只更新价格和产品变化部分。」

**注意：**上传的 PDF、图片等源文件可以通过资源库或知识库读取。文档面板、范围和历史见[助理文档库](/zh/docs/usage/agent/agent-documents)。

<a id="message" />

### 消息（Message）

**用途：**操作已配置的消息渠道，并管理相关 Bot 和连接。

**启用后可以：**在渠道支持的范围内发送、读取、编辑和管理消息，查看或管理 Bot 连接和消息路由。

**试着说：**「把确认后的项目摘要发送到已连接的团队频道，发送前让我检查。」

**注意：**先配置平台与有效连接。可读取的历史记录、编辑和删除操作因平台而异。Bot 接入与下表中的 Slack、WhatsApp 服务连接器是不同配置，参见[消息渠道](/zh/docs/usage/channels/overview)。

<a id="image-generation" />

### 图片生成（Image Generation）

**用途：**在对话中调用 LobeHub 配置的图片模型，而不要求当前聊天模型本身输出图片。

**启用后可以：**查询可用模型与参数，提交图片生成请求，查询生成状态。

**试着说：**「生成横版产品宣传图，主体在右侧，左侧留出标题区域。」

**注意：**需要可用图片模型、服务商配置与额度。尺寸、参考图等参数取决于模型。添加工具后，还需检查当前会话的运行模式能否使用该工具。

<a id="credentials" />

### 凭据管理（Credentials）

**用途：**辅助处理第三方账户授权和敏感凭据。

**启用后可以：**发起支持的连接流程，通过安全入口保存凭据，并在支持的云端执行环境中提供所需环境变量。

**试着说：**「引导我安全连接服务，不要让我把密钥发到对话中。」

**注意：**向云沙盒注入凭据，不等于向本地设备提供凭据。凭据是否可用取决于执行位置。

<a id="calculator" />

### 计算器（Calculator）

**用途：**执行数值计算与符号数学运算。

**启用后可以：**计算表达式、使用变量、排序、进制转换、解方程，以及求导、积分、极限等。

**试着说：**「按每月增长 3% 计算未来一年的收入，列出逐月结果。」

**注意：**计算器不获取外部数据。计算前，可以先用其他工具查询所需的实时汇率或价格。

<a id="artifacts" />

### Artifacts

**用途：**在独立预览面板中展示和迭代视觉或交互作品。

**启用后可以：**生成 HTML 网页、React 交互组件、仪表盘、SVG 图形和简单浏览器游戏；通过后续对话修改配色、布局或交互。

**试着说：**「做一个可切换月度和年度价格的套餐对比页，直接预览；然后加深色模式。」

**注意：**普通文章和代码解释留在对话中；持续维护的文本用 Documents；模型生成图像用 Image Generation。准备自包含预览时，无需启动云沙盒。外部 API、资源和浏览器权限可能受预览环境限制；该技能不支持通用的 PDF、PPTX 导出。查看预览并测试交互，按面板可用操作查看、复制或保存代码。

<a id="lobehub" />

### LobeHub

**用途：**指导助理通过 LobeHub CLI 操作平台资源。

**启用后可以：**在环境和权限允许时，管理助理、话题、文档、知识库、模型、插件和 Bot 等资源。

**试着说：**「把这个助理的开场白改为适合客户研究的版本。」

**注意：**需要实际可用的 CLI 和账户权限。技能中的操作说明不会绕过权限，也不会自动执行修改。

<a id="agent-browser" />

### 助手浏览器（Agent Browser）

**用途：**用于浏览器和 Electron 页面自动化。

**启用后可以：**导航页面、点击、填写表单、截图和提取内容，适合需要真实页面交互的网站。

**试着说：**「打开产品后台并整理本月数据；遇到登录时让我接手，不要提交修改。」

**注意：**使用助手浏览器需要支持设备执行的环境；可在桌面端技能商店中添加。它不同于系统管理的 Browser 工具和网页搜索，参见[内置浏览器](/zh/docs/usage/agent/built-in-browser)与[执行设备](/zh/docs/usage/agent/execution-devices)。

### 网页搜索、记忆和知识库在哪里？

网页搜索和记忆可在输入框的 **+** 菜单中单独设置。知识库需要为助理关联相应资料；本地系统和沙盒取决于所选执行环境。这些功能不一定需要从技能商店添加。

### 授权与工具权限

连接成功不等于开放所有资源。单个工具可能被设置为自动执行、需要审批或禁用，具体以配置为准，**不要假设所有写操作都会自动要求确认**。对助理禁用工具与撤销服务授权是两回事。

## 社区 Skills 和 MCP

你可以在 LobeHub 社区找到第三方 Skills 和 MCP，在 **Agent 页面 → 输入框 + → 技能 → 添加技能…** 打开商店后，可在 **Skills** 或 **MCP** 标签查找并添加。

- **Skills** 包含说明、工作流程和参考资料，部分包含脚本。先检查来源、依赖和权限，再安装使用。
- **MCP** 连接外部工具，添加后可能需要服务地址、认证或执行环境。详见[MCP 市场](/zh/docs/usage/community/mcp-market)。

安装前查看扩展说明与权限要求，只使用可信来源的扩展。需要外部服务或脚本的扩展，请先完成授权或配置执行环境。

<a id="import-skills" />

## 导入自己的 Skills

依次点击 **Agent 页面 → 输入框 + → 技能 → 添加技能…**，进入商店后点击右上角 **添加**，选择 GitHub、URL 或 ZIP。

### 从 GitHub 导入

1. 选择「从 GitHub 导入」。
2. 输入公开仓库地址，或包含技能的完整目录链接。
3. 确认导入，检查解析出的名称、说明和资源。
4. 回到技能列表，按需要设为自动或固定启用。

选择包含有效 `SKILL.md` 的目录。技能在子目录时，使用该目录的链接，并在链接中写明分支，尤其是分支不是 `main` 时。若链接无法导入，可将技能打包为 ZIP 后上传。

### 从 URL 导入

1. 选择「从 URL 导入」。
2. 输入公开可访问的 `SKILL.md` 直接链接或支持的技能包 URL。
3. 确认导入并检查结果，再为助理选择使用模式。

请使用技能文件或包的直接链接，而不是介绍页。LobeHub 需要能访问并读取文件，因此内网或受保护地址可能无法使用。

### 上传 ZIP

1. 将 `SKILL.md` 与所需参考资料、脚本打包为 ZIP。
2. 选择「上传 Zip」，点击选取文件或拖入文件。
3. 等待上传和解析完成，检查导入结果。
4. 为当前助理设为自动或固定启用。

建议将 `SKILL.md` 放在根目录，或单个一级目录中：

```text
my-skill/
├── SKILL.md
├── references/
└── scripts/
```

界面也接受 `.skill` 文件，按 ZIP 技能包解析。请分别打包各个技能；暂不支持批量导入深层目录中的多个技能。导入不会自动安装依赖，也不会赋予脚本任意执行权限。

## 常见问题

**已安装，为什么助理没有使用？** 检查当前助理是否禁用了该工具或技能、自动激活是否关闭，再核对运行模式、模型工具调用能力、服务授权、设备连接和依赖。固定启用不能绕过这些要求。

**Documents、Artifacts、图片生成怎么选？** 持续维护报告、笔记用 Documents；网页、交互组件和 SVG 用 Artifacts；图片模型生成的图像用 Image Generation。

**为什么没有找到某个连接器？** 可用项目可能因客户端、部署设置和账户权限而不同。请检查技能商店中显示的条目，并确认当前账户具有添加权限。
