# Webhook

Webhook 给助理一个 URL。其它系统向它发送请求时（比如 CI 失败、监控告警、表单提交，或者一段脚本），助理就会带着请求内容运行。不需要签名，也不需要特定格式：把 URL 和密钥交给对方系统就可以了。

## 创建 Webhook

1. 打开助理，进入 **助理档案 → Webhook**。
2. 点击 **创建 Webhook**。所有字段都是可选的：
   - **名称**：调用和对话里显示的名字。
   - **希望助理做什么？**：每次调用都会附上的任务，例如「总结失败原因，如果是新问题就创建一个 issue」。助理会把请求本身当作数据，而不是指令。
   - **话题**：**新话题** 让每次运行开启一个新话题，排队中的多次调用会合并到这一次运行里处理；**同一个话题** 把所有调用都放进一个话题，助理能看到之前的调用。选择同一个话题时，可以挑一个你与这个助理的已有话题续写，也可以让 Webhook 使用自己的话题。
   - **自动批准工具调用**：见 [审批](#审批)。
3. 在确认页复制 URL 和密钥，一起交给需要调用助理的系统。

密钥只会显示这一次：LobeHub 会加密保存它，之后无法再次显示。URL 不会变，随时可以在 Webhook 上复制。拿到密钥的人都能唤醒助理，请妥善保管。如果丢失或泄露，点 **生成新密钥**：旧密钥会立即失效，URL 保持不变。

## 调用

最简单的调用：

```bash
curl -X POST 'https://your-lobehub/api/webhooks/inbound/<id>' \
  -H 'Authorization: Bearer <key>' \
  -d 'Disk almost full on web-1'
```

- **请求体不限格式**：JSON、表单或纯文本都可以，最大 256 KB。query 参数也会一并交给助理。
- **密钥**：始终通过 `Authorization: Bearer <密钥>` 发送。URL 里不含密钥。
- **线程**：加上 `?thread=<key>`（或请求头 `X-Thread-Key`）。相同 key 的调用会续在同一个话题里，适合同一个工单或同一个 PR。
- **重试**：带上 `Idempotency-Key` 请求头。相同 key 的重试会直接确认，不会再次运行助理。

调用成功时立即返回 `202 {"id": "...", "status": "accepted"}`，助理在后台运行。其它返回：

| 状态码   | 含义                                |
| ----- | --------------------------------- |
| `401` | 缺少密钥、密钥不对，或已被新密钥替换。               |
| `409` | Webhook 已停用。                      |
| `410` | Webhook 已删除。                      |
| `413` | 请求体超过 256 KB。                     |
| `415` | 不支持文件上传（`multipart/form-data`）。   |
| `429` | 本分钟内工作区的调用太多，请按 `Retry-After` 重试。 |

## 查看运行情况

Webhook 开出的话题不会出现在主话题列表里。正在运行的话题会出现在收件箱，运行结束的话题会标为未读。在话题管理器里按 **Webhook** 筛选，可以看到全部。

在 Webhook 上点 **最近调用**，可以看到每次调用的接收时间、助理是否运行、请求内容，以及运行所在的话题。**发送测试** 会走和真实调用完全一样的路径发送一次示例调用。

每次运行都会消耗额度。同时排队的调用会合并到一次运行里处理，每次最多 20 条（不同线程的调用分开运行），剩下的随后接着运行。限额如下：

- **调用**：工作区每位成员每分钟 120 次（个人空间按一位成员计），该空间内所有 Webhook 和事件订阅合计。超出的调用返回 `429`，不会被记录。
- **运行**：一个 Webhook 每 10 分钟最多运行助理 30 次，超出的调用会被记录并跳过。
- **数量**：每位成员在一个工作区（或个人空间）里最多 50 个 Webhook 和事件订阅，工作区按每位成员 50 个计算上限。

## 审批

默认情况下，Webhook 唤醒的运行遵循你的工具审批设置，和你自己发消息时一样：需要审批的工具会停在话题里，等你确认。

打开 **自动批准工具调用** 后，这个 Webhook 的运行会直接使用工具、不再等待。只在你信任其密钥持有方的 Webhook 上开启：拿到密钥的人都能让助理执行操作。标记为必须确认的工具仍会等待。

## 停用或删除

用 Webhook 上的开关停用它：恢复前的调用都会以 `409` 被拒绝。**删除** 会永久移除它、它的 URL 和密钥。**设置 → Webhook** 列出所有助理的 Webhook，可以同样管理；新建需要在助理的页面上进行。

Webhook 的名称是给人看的，随时可以重命名。助理通过它的 **标识** 来识别它：标识在创建时按名称生成，之后不再改变（显示在 Webhook 上，例如 `ci-alerts`），所以重命名不会影响助理指令里对它的引用。

## 把结果发到频道

Webhook 可以把每次运行的回答，以助理消息的形式发到一个频道或频道里的某个线程，而不是留在需要你打开的话题里。运行本身仍在自己的话题中进行，只有最终回答会发到频道；如果没有值得说的内容，助理不会发消息。

这项设置通过 [`lh` CLI](#在-cli-或对话中管理) 完成（`--channel <频道 ID>`，发到线程时再加 `--thread <线程 ID>`），也可以在该频道或线程里直接让助理设置。你和助理都必须是该频道的成员。频道里没有人能审批工具调用，所以这类运行从不等待审批，发到频道必须打开 **自动批准工具调用**；标记为必须确认的工具会被跳过。

在网页上，这类 Webhook 会显示它发往哪里，可以删除，但只能通过 CLI 或在对话中修改。如果发送被拒绝（例如助理已离开频道），Webhook 上会显示原因。

连接器事件订阅（自动化）也可以发到频道：在频道或线程的消息里让助理订阅，之后每个事件的结果都会发回那里（在线程中订阅时，也可以要求发到频道主时间线）。

## 在 CLI 或对话中管理

Webhook 页面上的操作都可以用 `lh` CLI 完成：`lh webhook list`、`view`、`create`、`edit`、`pause`、`resume`、`rotate-key`、`test`、`calls` 和 `delete`。连接器事件订阅属于自动化，不是 Webhook，有自己的命令：`lh automation list`、`view`、`rename`、`check` 和 `delete`。`create` 和 `rotate-key` 会输出一次密钥，方便脚本把 Webhook 接到其他系统。

在对话中，助理可以列出、创建、修改、测试和删除自己的 Webhook，这些操作遵循你的审批设置；它的事件订阅由连接器事件工具管理。助理始终看不到密钥：它创建的 Webhook 会在对话里显示 **生成密钥** 按钮，点击后密钥只向你显示一次。
