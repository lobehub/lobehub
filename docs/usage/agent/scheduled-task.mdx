# Agent Tasks

**Tasks** lets you assign work to an Agent, track progress, and review results. On an Agent page, you can manage tasks for that Agent, run one-off work, or configure recurring runs.

## Opening Tasks

Click **Tasks** on an Agent page to view tasks for that Agent. This page shows only the current Agent’s tasks. New tasks belong to that Agent, so you do not need to select an assignee.

## Creating a Task

1. Click **Tasks** on the Agent page.
2. Describe the work in the **Add task instruction...** input at the top of the page.
3. Optionally, set a priority or use the attachment icon to add relevant files.
4. Click **Create task**.

Include the goal, relevant background, and expected output in your instructions. For example:

> Read the attached customer feedback, group it by issue type, and identify the three most common problems. Suggest an improvement for each problem and present the results in a table.

The current Agent appears below the input. Before creating the task, check that the Agent can access the tools and materials it needs.

## Tracking Progress

After creating a task, find it in the list below the input. Tasks are grouped by status, such as **Pending review** and **Backlog**, to help you find work that needs attention.

Click a task to open its details and review progress, run records, and output. Open linked topics or artifacts to inspect the deliverables.

## Configuring Scheduled Runs

Automation settings in the task detail control recurring runs. You can set the frequency, time, and execution cap.

1. Open the task from **Tasks** on the current Agent’s page.
2. Open **task detail → Automation → Scheduled**.
3. Configure the frequency, time, timezone, and execution cap.
4. Enable automation.
5. Start scheduling through the available control.
6. Check the task status and next run time.

### Configuration Fields

- **Task name and instructions**: State the objective, data sources, output format, and delivery requirements. Include necessary background rather than relying on an earlier chat.
- **Frequency**: Choose from **Daily**, **Weekly** (multiple weekdays), and **Hourly** (an integer from **1 to 24**).
- **Time**: Use 24-hour time in half-hour slots. Minute choices are **00** or **30**.
- **Timezone**: Select the intended timezone and check the preview. If no timezone is saved, the form uses **UTC**.
- **Max runs**: Set an execution cap, or choose continuous execution. For a once-daily schedule that runs as expected, 30 runs covers 30 days. Other schedules cover different periods.

### Scheduled vs. Fixed Interval

**Scheduled** runs at clock-based times. **Fixed interval** repeats work at a specified interval, with a minimum of **10 minutes** or **1 hour**. For a specific time of day, choose Scheduled.

Scheduled runs support Daily, Weekly, and Hourly schedules, but **not Monthly or custom cron expressions**. After editing a schedule, check the saved settings and next run time.

### Schedule Examples

| Work | Schedule | Instructions |
| --- | --- | --- |
| Morning report | Daily at 08:00 in the selected timezone | Summarize yesterday's metrics, cite the source, and list missing data. |
| Competitor review | Weekly on Monday at 09:00 | Check the specified competitors and report pricing changes with links. |
| Monitoring summary | Hourly, every 2 hours | Check the configured source and summarize new alerts. |

First test the instructions on demand. Before you enable repeated runs, check that the assigned Agent has the required tools, permissions, and access to an execution environment.

## Managing Tasks

### Viewing Results

Click a task in the current Agent’s task list to inspect run records, outputs, errors, and Acceptance reports. Open linked topics or artifacts to review the results.

### Editing a Schedule

Return to **Automation** to change the frequency, time, timezone, or execution cap. Check the saved configuration and next run time. For work already in progress, check its run status separately.

### Disabling Automation

Turn off automation to stop future automated runs while retaining the task and its saved configuration. Before re-enabling, check that the run mode, frequency, and next run time match your needs. For a run already in progress, check its status separately.

### Deleting a Task vs. Disabling Automation

**Delete the task only when you intend to remove the work record**, not merely pause its schedule.

Deleting a task removes its record and task-level data, including comments, activities, dependencies, and links to topics or documents. Linked content and child tasks have separate deletion scopes.

Before deleting, save needed results and check whether the selected operation includes child tasks. Review linked topics, documents, and files separately.

## Acceptance and runtime requirements

Configure [Acceptance](/docs/usage/agent/connectors#acceptance) for your output requirements. After each run, review the result and check report.

Before enabling automation, run a test to check access to the required files, services, and execution device. Keep the execution environment available for scheduled runs. If the task includes sending email or messages, configure and authorize the corresponding tools.

## Troubleshooting

- **No expected run**: Check that automation is enabled, scheduling has started, the execution cap has not been reached, and the timezone is correct. Inspect the task status and errors.
- **Unexpected timing**: Check 24-hour time, timezone, and whether you selected Scheduled or Fixed interval.
- **Missing context or poor output**: Put the required background, data sources, and output criteria in the task instructions. Check that the Agent can access the required tools and data.
- **Too many runs or excessive cost**: Disable automation first, then correct the frequency and execution cap.
