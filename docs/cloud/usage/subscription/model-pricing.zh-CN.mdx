# LobeHub 积分计费规则

<CloudOnlyAlert />

LobeHub Cloud 使用 **积分（Credits）** 记录内置模型服务的用量。不同模型和不同类型的输入、输出价格不同，因此相同数量的 token 可能消耗不同积分。

## 积分如何换算

为便于计算，LobeHub 将 **1 美元的模型用量折算为 1,000,000 积分**。

例如，某模型的输入价格为 `$3 / 1M tokens`，每个输入 token 对应 3 积分；使用 1,000 个输入 token 时，约消耗 3,000 积分。

实际扣除以请求完成后的用量和模型当时的价格为准。你可以在模型详情中查看当前定价。

## 文本对话如何计费

文本模型通常分别计算：

- **输入 token**：当前消息、系统提示词、对话历史、文件内容和工具返回内容等发送给模型的信息。
- **输出 token**：模型生成的回复，包括部分模型产生的推理内容。
- **缓存读取与写入**：支持提示词缓存的模型会按各自的缓存价格计算，通常与普通输入价格不同。

| GPT-5.6 Terra | 1.05M | 2M～4M 积分 | 12M～18M 积分 | 0.2M～0.4M 积分 |
| GPT-5.6 Luna | 1.05M | 0.2M～0.4M 积分 | 1.2M～1.8M 积分 | 0.02M～0.04M 积分 |

GPT-6 Astra 和 GPT-5.6 系列以 272K 输入 token 为分界；Grok 4.6 以约 200K 输入 token 为分界。表中 DeepSeek 和 GLM 的人民币标价按代码中的 `1 美元 = 7.12 元人民币` 换算为积分，并四舍五入显示。

例如，使用 Gemini 3.8 Flash 发送 10,000 个普通输入 token，并生成 2,000 个输出 token：

- 输入：`10,000 × 0.75 = 7,500` 积分
- 输出：`2,000 × 3.75 = 7,500` 积分
- 合计：约 `15,000` 积分

如果其中 8,000 个输入 token 命中缓存，则这部分会按缓存读取价格计算，实际消耗会更低。最终扣除仍以请求返回的实际用量为准。

> 以上模型和价格依据 GitHub 当前模型配置整理。模型上下架或服务商调价后，页面中的模型详情会同步变化，请以使用时显示的价格为准。

对话越长，每次请求携带的历史内容通常越多，积分消耗也会增加。切换话题时开启新对话，可以减少不必要的历史输入。

<Callout type={'tip'}>
  使用网页抓取、文件、知识库或工具时，相关内容可能作为输入发送给模型，并计入本次请求的输入用量。
</Callout>

## 分梯度与参数化定价

部分模型采用分梯度定价：当输入长度超过指定阈值后，超出部分或整次请求可能使用更高费率。例如，部分 Gemini Pro 模型在输入超过 200K token 后会进入更高价格档位。

部分缓存、图像或视频模型还会根据缓存时长、图像尺寸、分辨率、时长等参数选择价格。具体规则以模型详情中显示的计价单位和费率为准。

## 图像、音频和视频如何计费

多模态模型会根据模型支持的计价单位扣除积分，常见方式包括：

- 每 1M token
- 每 1M 字符
- 每张图片
- 每个视频
- 每百万像素
- 每秒

同一项任务使用不同模型、尺寸、质量或时长时，积分消耗可能不同。

## 查看价格与用量

- 在模型选择器中打开模型详情，可以查看输入、输出、缓存和多模态项目的当前价格。
- 在 **应用设置 → 套餐 → 用量** 中，可以查看当前计费周期的用量。
- 如果积分不足，可以升级套餐、购买积分包，或配置自己的模型 API Key。

<Callout type={'info'}>
  使用自定义模型 API Key 时，模型费用由对应服务商按照其账户和价格规则收取，不从 LobeHub Cloud 的内置模型积分中扣除。
</Callout>
