## What

`src/store/user/slices/workspaceUserSettings` drops its raw `useClientDataSWR` read and its hand-written optimistic write/rollback for a `@lobechat/replica` resource, following the merged reference slices (`src/store/task`, `src/store/project`, `src/store/chat/slices/topic`).

Single-resource scope: no session / message work here.

## How

- **`projection.ts` (new)** — a typed `workspaceUserSettings` resource: `key = workspaceId`, persisted to IndexedDB, `TData = WorkspaceUserPreference` (`TFetched = … | null`, a missing server row folds to the empty bucket). The identity partition `${userId}:${workspaceId}` already owns the workspace boundary, so a workspace switch is a scope change and the fetcher stays workspace-agnostic (the tRPC context carries it), exactly as before.
- **`initialState.ts`** — adds the replica bookkeeping slot; the view stays on the long-standing `workspaceUserPreference` + `workspaceUserPreferenceWorkspaceId` fields.
- **`action.ts`** — `createReplicaSlice` with a single-slot lens (only the active workspace is materialized; the marker gates it) + `useSync`. `useFetchWorkspaceUserPreference` keeps the exact `{ data, isLoading, mutate }` shape the consumers already use, and `updateWorkspaceUserPreference` merges the patch optimistically through the engine and rolls back on failure.
- **No consumer changed.** Every selector (`workspaceUserSettingsSelectors`) and reader (chat-input model/device/mode pickers, `useEffectiveAgencyConfig`, sidebar bridge, send-time `agentConfigResolver`) keeps reading the same fields.

Side effect of the migration: the bucket now paints from the local projection on reload and revalidates in the background, instead of starting empty until the network answers.

## Module cycle fix (required)

The user store is the first store to import `@/libs/replica`, which closes a cycle: `@/libs/replica → @/libs/swr/useCacheScope → @/store/user → @/libs/replica`. When `useCacheScope` is evaluated first, `@/libs/replica`'s body used to **read** `useCacheScope`'s still-uninitialized exports and bake `undefined` into `cacheScope` — every replica resource then got a scope with no `get`/`use`/`canPersist` (the `ConversationControl` suites reproduced it).

- `src/libs/replica/index.ts`: `cacheScope` delegates at call time instead of capturing the exports at module-eval time (equivalent — they are stateless delegating functions). A regression test (`cacheScope.cycle.test.ts`, `useCacheScope` imported first) fails before the fix and passes after.
- the user-store replica binding is created on first use rather than during store init (the constructor runs while the user store module is still initializing), and the initial bookkeeping slot is written as its literal `{ entries: {} }`.
