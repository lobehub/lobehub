## 验收限制与待确认

- F12–F14 依赖完整模型请求链路和模型上下文观测能力；如当前隔离环境无法读取下一轮请求体，记录为未验证并先补可审计观测，不能用 fixture 内部状态冒充注入证据。
- Flag 必须通过产品实际配置路径分别打开和关闭，并记录值；只切换 localStorage 或改代码常量不构成 flag 验收。
- 工具可见性 / 禁用需由产品工具配置与真实调用链验证，不以 MCP `tools/list` metadata 单独证明产品行为。
- 本文记录场景与执行口径；正式结论、原始截图、请求记录及独立复核结果以发布的验收报告为准。没有证据的边界不记为产品实测通过。

## 产品证据与单测辅助边界

- 产品 UI / 真实链路主证据：F01–F18、F20–F30 中涉及入口、自动打开、历史行为、topic、上下文、真实 MCP transport /device identity、mobile 或 PiP 的行为。须在当前分支全栈操作并留截图及请求观测；fixture 只提供可控输入，不代表产品通过。
- 需 UI 交互加协议时序：F19、F29、F31。真实 app 按钮与 host bridge 是主证据；单测补充能力交集、隐藏状态和迟到 / 重复 ACK 边界，不能只靠 mocked bridge 判通过。
- 单测辅助但不能独自通过产品项：模式优先级 / 交集、store key 与恢复、group 归属、listener 去重、工具可见性 / 禁用策略、deviceId 映射、context diff /dedupe/cleanup、teardown 状态机。引用当前分支相关测试结果，并保留 UI 链路证据。
- fixture 提供可控的 MCP 元数据、App 协议事件和模型响应；旧 CSP、模型上下文注入、mobile / PiP、HTTP /stdio 设备归属与隐藏 pane 行为均经过真实产品链路观测。模型是隔离环境的受控 fixture，并非外部商用模型。
- 模型 fixture 需要隔离账号下稳定可用、支持多轮对话和工具调用的模型，并能逐轮查看发往模型的完整 message/context payload。F12–F14、F24–F25 及 F15 的真实工具禁用判断依赖此观测；不可观察 payload 时不能宣称上下文 case 通过。

## 本轮执行边界

- Web、mobile SPA 和桌面均连接运行本分支的隔离后端；没有将生产 Debug Proxy 当作验收 surface。HTTP 与 stdio 在同一物理测试机器上分别经过服务端中转和桌面本机 IPC，未验证跨物理机器的 device gateway 网络。
- 桌面 classic 聊天路径沿用 canary 的用户级 connector 工具发现逻辑；stdio fixture 使用用户级 connector。Agent 专属 connector 在该既有路径中的发现问题未在本任务中扩展修复。
- F20 验证 assistant 消息组中的多工具结果归属，不等于群聊路由验收。群聊无侧栏的回退由宿主能力边界与单测覆盖，本轮没有单独运行群聊页面 UI 用例。
- inline 与侧边面板迁移会重新挂载 iframe，以保证同一 toolCallId 同时只有一个活实例；隐藏面板保留实例和 bridge。App 内部临时状态不跨迁移保留，widgetState 不在本期范围。
- 执行早期的资源 guard 采样不连续；正式报告保留该边界。环境依赖缓存、桌面认证和旧人工介入操作的诊断日志与功能失败分别记录，不能据此宣称整轮 console 从未报错。
- F25 的真实产品操作覆盖 teardown 和离开会话；resource identity 改变的清理由单测补充，本期没有切换 resource 的用户入口。
