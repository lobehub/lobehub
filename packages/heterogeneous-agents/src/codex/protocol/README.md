# Codex app-server protocol

`generated.ts` vendors the stable TypeScript protocol emitted by Codex at revision
`5e32f728f1f86a967c6be057351f12505778df8f`.

Generate the upstream files with:

```bash
codex app-server generate-ts --out <directory>
```

The `ThreadUnsubscribe*` types come from the same command run by Codex CLI 0.160.0, where
`thread/unsubscribe` is part of the stable request set.

The vendored file is the transitive stable subset used by LobeHub's native app-server client. Keep
wire names and nullability identical to the generated files; do not hand-edit protocol types.

`experimental/ToolRequestUserInput*.ts` are generated by Codex CLI 0.166.0's
`codex app-server generate-ts --experimental --out <directory>` output. They describe the
native `item/tool/requestUserInput` request and its question-id-keyed answer contract;
only repository formatting is applied after generation.

The Codex Plan switch (collaboration mode) files are generated by Codex CLI **0.169.0**'s
`codex app-server generate-ts --experimental --out <directory>`:

- `experimental/CollaborationMode.ts`, `ModeKind.ts`, `Settings.ts` and their imports
  (`ReasoningEffort.ts`, `Personality.ts`, `ReasoningSummary.ts`, `MultiAgentMode.ts`,
  `AbsolutePathBuf.ts`, `LegacyAppPathString.ts`);
- `experimental/v2/PlanDeltaNotification.ts` (`item/plan/delta`);
- `experimental/v2/ThreadSettingsUpdateParams.ts`, `ThreadSettingsUpdateResponse.ts`,
  `ThreadSettingsUpdatedNotification.ts`, `ThreadSettings.ts` and their imports
  (`ActivePermissionProfile.ts`, `ApprovalsReviewer.ts`, `AskForApproval.ts`, `NetworkAccess.ts`,
  `SandboxPolicy.ts`, `ThreadEnvironment.ts`, `TurnEnvironmentParams.ts`).

They keep the generator's relative layout so imports resolve unchanged. `turn/start.collaborationMode`
and `ThreadResumeResponse.collaborationMode` are experimental fields the stable `generated.ts` does not
carry; callers add them to the stable params type at the call site. The plan `ThreadItem` is already in
the stable set.
