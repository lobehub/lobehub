# CLI command → REST endpoint coverage

`apps/cli` (`lh`) started out calling the internal tRPC routers for everything. The C1 pilot moved the commands whose REST endpoints behave the same onto `@lobehub/sdk` (`apps/cli/src/api/sdk.ts` → `getSdkClient()`), as a test of the SDK. This file maps all **497** leaf commands to the public REST API and is the gap list for later work.

- Endpoints are relative to `/api/v1`. **SDK method** is the `operationId` (`lobehub.<resource>.<method>`), read from `packages/openapi/openapi.yml` on this branch or from the sibling PR's spec (which may still rename it before merging).
- **Transport now** is what the command calls after this change.

Where a command is kept on tRPC, the public endpoint usually behaves differently from the internal router it would replace: built-in models and providers aren't merged in, list filters and fields are missing, delete side effects differ, and for agent, file and kb, permission and visibility checks are missing. `agent edit`, `file list --kb-id`, `kb edit`, `kb add-files` / `remove-files` and `provider create` were first moved to REST, then moved back after the independent review found the REST paths skip or tighten checks the tRPC procedures enforce, or report errors differently. These are product decisions for the REST layer, not SDK problems. They're listed in [REST endpoints that need to change](#rest-endpoints-that-need-to-change) below. The SDK itself only needed a small change during migration (see [SDK changes found by the pilot](#sdk-changes-found-by-the-pilot)).

### Auth and workspace on the SDK path

`getSdkClient()` resolves credentials in the same order as the tRPC client (`pickAuthSource`):

- `LOBEHUB_JWT` is sent as `Authorization: Bearer`.
  - It is read again on every request, because `hetero exec` renews it in place.
  - A run's `hetero-operation` token is swapped for this machine's stored login of the same account, which is the rule `operationTokenFallbackLink` applies to tRPC.
- `LOBEHUB_CLI_API_KEY` is sent as a Bearer API key.
- Otherwise the stored OIDC login is used, re-read and refreshed for each request.

`X-Workspace-Id` is resolved the same way every other command resolves it: explicit id → `LOBEHUB_WORKSPACE_ID` → `lh workspace use` → personal.

## SDK changes found by the pilot

- **`paginate(method, options, { maxItems })`** (`packages/sdk/src/pagination.ts`): migrated lists need "the first `--limit` items". Without a cap, each command wrote its own cursor loop. Now iteration stops at `maxItems`, and with a `query.limit` the last request asks only for the items still needed. Without one, pages keep the server's default size, so the SDK never sends a page size above an endpoint's cap. `lh goal list` uses it.
- **Works as is:**
  - `throwOnError: true` with `LobeHubAPIError.status` / `.code`: the 404 → `X not found` mapping works without parsing bodies.
  - `accessToken: () => …` per-request credentials.
  - `workspaceId`.
- **Friction, left as is:**
  - The envelope makes every read `data.data` (`{ data: { data, success } }`).
  - Several REST services return their error messages in Chinese (`已存在`, `仅创建者或工作区所有者可修改此知识库`), so a CLI that printed English errors would print Chinese ones. `provider create` stays on tRPC for that reason (its duplicate answer is a `400`, not a `409`); the messages need fixing on the server.
  - `GET /tasks` paginates by offset, unlike the cursor lists, so `paginate` can't walk it.
  - Both are REST contract choices, not SDK bugs.

### Server version

Migrated commands need a server that serves these routes: `/api/v1/tasks` (list, get, create, update, status, delete), `/api/v1/goals` (list, pause, resume, delete, restart), `POST /api/v1/knowledge-bases`, and `PATCH|DELETE /api/v1/providers/{id}`. The CLI already depends on `/api/v1/users/me`.

On an older self-hosted server that lacks one of these routes, the request gets a 404. `provider edit` / `delete` then report "not found" for a route that doesn't exist yet.

## REST endpoints that need to change

These come from the `tRPC — REST differs` rows. Each one blocks migrating a command in the pilot scope:

1. **Permission and data-safety checks**
   - `GET /knowledge-bases` and `GET /knowledge-bases/{id}/files`: missing the ownership / visibility / restricted-library checks.
   - `PATCH /agents/{id}`: missing the share-model lock and collaborative edit access.
   - `POST|DELETE /knowledge-bases/{id}/files/batch`: creator-only rule instead of `knowledge_base:update`; batches apply partially.
   - `PATCH /knowledge-bases/{id}`: creator-only rule instead of `edit` access to a shared library.
   - `DELETE /files/{id}`: removes storage without the `REMOVE_GLOBAL_FILE` / shared-hash check.
   - `DELETE /knowledge-bases/{id}`: no guard for dedicated agent/project libraries.
2. **Models and providers**
   - `GET /models` and `GET /providers` should merge the built-in model-bank entries.
   - `PATCH` should upsert built-in rows.
   - `GET /providers/{id}` should be able to return `keyVaults`.
   - Add `model view` by bare id, or add a `--provider` option to the CLI.
3. **Agents**
   - Public agent: add `name`, `tags`, `visibility`, `workspaceId`.
   - List: add an inbox option and a `tag` filter.
   - Create: make `title` optional; add `tags`, `groupId`, `visibility`, and the direct Channel.
   - Delete: recycle bin and owner guard.
   - Duplicate: access level.
   - Edit: workspace edit lock.
4. **Topics and messages**
   - `GET /topics`: filter by `topics.agentId`, exclude channel topics, order by last activity.
   - `GET /messages`: add `agentId` and date filters and a sort order, drop the `topicId` / `userId` requirement, return the agent name.
   - Transcript endpoint (PR #23254): must accept run operation tokens.
5. **Tasks and goals**
   - `GET /tasks`: add `parentTaskId` / archived / label filters and `participants`.
   - `POST /tasks`: add `labelIds` and `context`.
   - `PATCH /tasks/{id}`: add `heartbeatTimeout` and `configPatch`.
   - `GET /goals`: add an archived switch.
   - `POST /goals/{id}/resume`: support `confirmExit` and return the turn-cap message.
   - `POST /goals`: create without starting.
6. **Error messages**
   - REST services answer in Chinese; return English (or locale-aware) messages.
   - `POST /providers`: answer a duplicate id with `409` (`createConflictError`), not `400 BusinessError`.
7. **Files**
   - `POST /files`: add `parentId` and raise the size cap.
   - `PATCH /files/{id}`: add `parentId`.
   - Add file detail with chunking status.
   - Add recent files and knowledge items (documents + folders).

## How this table was built

- Leaf commands: walked `createProgram()` (hidden commands excluded).

- Transport: each leaf's `.action()` source plus up to 3 levels of CLI helper functions, scanned for `<router>.<proc>.(query|mutate|subscribe)(`; a few dynamic calls (`router[name].mutate`, helper-only files) were set by hand. Scope helpers (`workspace.getById`, `workspace.list`, `workspaceMember.list`, `taskLabel.list`, `user.getUserState`) are ignored when judging status.

- REST: paths from `packages/openapi/openapi.yml` on this branch (176 operations); sibling PRs' new operations from each PR branch's `openapi.yml` minus this base.

- Sibling PRs: #23253 runs, #23254 messages/topics, #23255 documents, #23265 retrieval/memory, #23267 generation, #23272 webhooks, #23274 skills/connectors, #23292 agent advanced, #23301 workspace/sharing, #23303 tasks/goals advanced, #23311 projects/widgets, #23315 settings/model-provider ops, #23316 devices, #23332 bots.

- "partial" = some procedures map to REST, at least one does not. The mapping is procedure-level; field-level parity is not checked here.

- Rows in the pilot scope were then rewritten with what each command actually calls after the migration, and with the reason it stays on tRPC (checked field by field against the REST service, not just procedure by procedure).
